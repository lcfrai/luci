# CLOUD-083 prospective installed cancellation helper

This external helper corrects two acceptance-driver limits. The original installed attempt never sent HTTP Cancel: its exact classic-builder RUN had logging driver `none`, so reading `docker logs` failed. The original controller later exited normally (code 0, signal null); its helper attempted escalation after 10 seconds. That observation does not prove a forced kill or product shutdown failure.

The successor writes one source-bound, nonce-bound proof atomically inside the exact owned RUN, reads it through a read-only Docker archive GET, and validates the archive entirely in memory. The archive is limited to 65,536 bytes, one regular `stage-proof.json` member of at most 16,384 bytes, no link/path overrides, and timestamp-only bounded PAX metadata. No extraction to the host occurs. The exact immutable container ID, all ten product labels, fresh fixture labels, RUN command, current age, 1 GiB memory/no swap and one CPU caps remain mandatory. Unknown build charges are never cleared by this helper. Archive requests have a three-second bound and parsing two seconds. Parent cancellation closes the archive read.

The controller grace is 20 seconds, covering the source's 10-second HTTP shutdown and subsequent five-second preview close with bounded margin. Any actual escalation still fails the run and is labeled attempted; process exit code/signal remains independently recorded. Total lifecycle, request counts, proof age, Cancel latency and settlement limits are unchanged. Disk admission retains the original 3,890,600,000-byte pre-spawn floor and independently requires current product admission. The exact ten-image baseline includes all nine original images and the retained `b668fcfe…` intermediate from the failed original; arbitrary image growth is refused.

Controlled evidence contains the unchanged test body against the original handler (expected unsupported-logging failure) and corrected handler (pass). The 54-case fixed batch had 53 passes and one test-only error-message expectation mismatch: oversized input was correctly refused. Only that matcher was corrected and the one affected case passed. The helper did not change after the batch. These inert tests cover exact request routing, parser bounds/types/path safety, cancellation, ownership/resource/source/age guards, and no mutation replay. They do not establish actual daemon compatibility or Windows behavior.

Runtime, if dispatched after the frozen gates pass, starts one isolated installed controller and one unique project/release build through Product HTTP. It does not use a browser, model, serving container, cold base pull, Docker exec, manual Stop, Docker removal or ledger edits. The RUN naturally exits nonzero after 45 seconds if cancellation does not settle. The proof must be observed while fresh and running before the one expected-revision Cancel request. Intent response duration is recorded separately from Start settlement and read-only daemon absence; daemon absence is never proof of authoritative build-stream settlement or grounds for capacity release. Remaining unknown work/lease state is retained for explicit supported recovery, not replayed. The original failed state and charged lease remain untouched.

Source package is exact edc742e8b6ce4216a1726e74cceef892663ce3d5, static extraction verified separately. No Go compilation or product source changes are part of this correction. Root grants one fresh preflight and one run only if all gates pass; a refusal is retained without lowering bounds.
