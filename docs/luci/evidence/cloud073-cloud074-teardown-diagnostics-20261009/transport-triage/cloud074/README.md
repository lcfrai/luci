# CLOUD-074 bounded monitor-disposal diagnostics

The warm and cold external scenario helpers add a synchronous `monitor.disposalSnapshot()` method. It returns a fresh deep clone of bounded first-call monitor/transport state and the existing safe protocol projection. It performs no page evaluation and retains no new error text, URLs, or frame payloads. Timestamps contain wall time and monotonic milliseconds. Call counts saturate at 16; `additionalCalls` records later calls, while first-call history is retained.

The method distinguishes disposal entry, page-listener removal, detach invocation/return, underlying detach settlement, and bounded-wait settlement. An outer timeout can capture pending state. A later detach acknowledgement or rejection changes only a fresh observer snapshot; captured and final receipt objects remain unchanged. An inner timeout's rejected wait remains rejected after a later acknowledgement. Existing repeated-dispose behavior remains unchanged; this diagnostic does not deduplicate or retry disposal.

The original eager detach invocation and 1,500 ms inner timeout remain in place. The parent owns launcher wiring and preserves the 2,000 ms outer timeout and original acceptance conditions. This component changes observation only and provides no timeout fix or success promotion.
