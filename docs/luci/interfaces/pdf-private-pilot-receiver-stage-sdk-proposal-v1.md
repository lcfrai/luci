## Receiver wire and stage contract

The trusted API starts from the persisted `pdfPilotLease`: scope digest, 16-byte attempt ID, exact role, deterministic `PDFPilotAllocationID(scope,attempt,role)`, input SHA-256 and selected engine/instance/CID. Backend role `renderer` maps only to driver `render` and wire `R`; `reader` maps only to driver `read` and wire `D`. **The frame has no explicit attempt field.** Its raw 32-byte allocation ID binds the attempt and scope through the existing deterministic derivation; the decoder recomputes that ID and compares it with both lease and frame. Renderer input must be the approved original font digest; reader input must be the durably retained renderer PDF digest. Frame bytes alone cannot provide actor, source or engine authority.

The API parser consumes the selected attach's **raw** Docker multiplex bytes. Every 8-byte header and payload counts against `34 MiB + 16 KiB`; fragmented headers/payloads and multiple bounded stdout frames are supported. Only nonempty stdout frames with the selected protocol's zero reserved header bytes are accepted. Stderr, other streams, malformed lengths, extra logical bytes after the end marker and early EOF refuse; no raw command output enters a receipt or log. An incremental state machine accepts exactly `LUCI-PDF-PILOT/1\n`, role, allocation digest, input digest, typed page-count byte, record count, ordered records and `LUCI-PDF-PILOT-END/1\n`, then exact transport EOF. Renderer requires page-count 0 and one `P` record; reader requires page-count 1 and ordered `T`,`N` records. Each header's big-endian length is checked against its per-type cap and remaining aggregate/stage allowance **before** allocation or write; bytes are streamed into SHA-256 and the API stage. The recorded length/hash must match the original payload exactly. Limits are PDF 16 MiB, text 1 MiB, PNG 16 MiB; text and PNG still receive their existing exact semantic checks. A complete frame plus EOF is only a **capture candidate**, never exit, retirement or acceptance.

The constructor uses the already trusted execution-state root and the exact persisted attempt/lease, creating `pdf-pilots/<AttemptID>` and role files under retained rooted handles. Only the API opens `renderer.pdf`, `reader.txt` and `reader.png` with exclusive no-replace creation; it never exposes a writable host mount. Any existing partial name after an uncertain result is readback-only, not truncated/reused. Per-file ordinary/single-link/no-follow and parent identity checks cover create, streaming writes, fsync, readback and final cleanup. An API receipt binds actor/scope/attempt/role/allocation, original input digest, selected CID, byte length, payload SHA-256 and host file identity; it is durable before the next effect. A failed write/fsync/publication retains the exact partial stage and unknown lease. API writes have hard per-object and aggregate bounds with no duplicate temporary copy; the 48 MiB disk charge is **admission accounting, not an OS quota**. A platform unable to prove private rooted storage, exclusive creation and positive cleanup refuses.

## Original identity and two serial SDK roles

The selected adapter uses the existing `Backend.api` engine/client and immutable `PDFPilotIdentity`; it constructs exactly one fixed driver command per role, a read-only root, `/out` 32 MiB and `/tmp` 8 MiB tmpfs under the 512 MiB memory/swap cap, CPU 1, PIDs 32, network/IPC none and no logging/other writable mount. The driver itself creates the required **empty** `/out/pilot-<AttemptID>` before invoking the writer. The renderer's font and reader's retained PDF are the only read-only input binds. Pre-Start inspect must match image, labels, command/env, numeric UID/GID, input namespace, tmpfs options and resource limits; unsupported settings refuse. The driver/binary paths, selected Poppler binaries/libraries and exact image remain unavailable and cannot be inferred from a host installation or preliminary Debian inventory.

An original-input guard must bind **both bytes and namespace** before Create, across pre-Start inspect and **every** driver/child reopen of `/input/NotoSansCJK-Regular.ttc` or `/input/pilot.pdf`, and through positive role retirement. Keep held ordinary file and ancestor handles, prevent replacement/rename/write while the role runs, and verify the selected Docker bind targets that exact object. The current driver rehashes before and after its fixed tools; those hashes do **not** close a namespace-swap interval. The reader's PDF is the exact API-owned renderer stage file after durable capture and positive renderer retirement. If the selected OS/engine cannot prove a held file-and-parent guard for its bind translation, both roles refuse; periodic path checks do not substitute. A failed guard close keeps the attempt uncertain and charged.

Before Start, Create is journaled once; an unknown Create ACK retains the allocation and permits only exact readback/retirement. On an exact known CID, arm the independent selected-client watchdog immediately, then establish and durably claim its bounded pre-Start stdout attach. Attach failure means **no Start**. Current actor/source/capacity and launch-fence authority are rechecked before the one Start; no change is copied into an existing attempt. Capture may proceed while the driver is alive, but its durable `CaptureAt` is published only after exact frame/EOF, a positive exited-zero/non-OOM observation and stage fsync. The watchdog's separate CID/engine call lane may retire before blocked attach, disk I/O or publication settles and never waits on their locks. Renderer retirement and validated capture precede reader Create/Start. Reader follows the same once-only attach, exit, capture and retirement rules. The child has at most 30 seconds including tools/capture; existing 40/40 phase ends and 120-second whole/cleanup envelope do not reset on retry. Full frames with missing/unknown exit, lost publication or unknown retirement stay unavailable; they cannot become accepted after a timeout or authorize a replacement role.

The API keeps the existing one-512-MiB charge, 64-MiB host-capture allowance and 48-MiB stage reservation while any role or cleanup outcome is unknown. Exact positive retirement is required before stage removal and charge release. Existing-child recovery preserves its original claim and evidence; no late attach to an exited tmpfs, `CopyFromContainer`, duplicate Start, host arbitrary-path read or text-as-tool conversion is allowed. Later positive readback records historical cleanup separately from timely pilot acceptance.
