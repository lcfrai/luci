# Preview build cancellation frontend evidence

This capsule records the frontend part of the CLOUD-080/082 follow-up. An exact live build can be cancelled while its original Start request is held. The UI separates a cancellation request from confirmed cancellation, retains uncertain outcomes, and requires an explicit later history refresh before retrying an uncertain request. It preserves current Deploy authority, project/read-generation boundaries, reviewed revision checks and normal Stop behavior.

## Contract

`POST /v1/product/projects/{project}/releases/{release}/cancel` sends only `expectedRevision`. Fresh request returns 202; an acknowledged retry with the original submitted revision may return 200. The returned exact local release must contain `cancelRequested: true` and a revision greater than the submitted revision; later producer progress may advance it by more than one. Permission or stale/nonlive refusals remain errors. Cancellation intent does not prove cleanup or release resources. The frontend consumes only the public revision/canCancel/cancelRequested fields, not private runtime identities or leases. A natural-ready race retains ready wording rather than announcing successful cancellation.
