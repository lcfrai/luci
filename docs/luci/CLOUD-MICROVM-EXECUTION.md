## What is implemented

`control-plane/internal/backend/backend.go` exposes Create, Get, List, Attach, Destroy and Close. The working default is Docker. Session creation supplies a host worktree, reviewed context and conversation mounts plus a working directory. The Kata adapter explicitly rejects Mounts and WorkDir and describes itself as dormant. Configuring `LUCI_BACKEND=kata` therefore does not deliver the current task workflow.

The existing catalogue enables Codex, Claude Code, OpenCode and Shell; availability of a CLI is distinct from a configured model connection and successful real-provider execution. No cloud microVM provider is supported by this revision. Do not offer E2B, Fly, AWS or Azure as interchangeable working execution choices. Existing remote workspace/provisioning capability is not evidence of microVM task execution.

## Implemented allocation and transfer boundary — CLOUD-084/088

`control-plane/internal/backend/e2bbe` introduces an unwired Go boundary; it does **not** implement a working `backend.Backend` selection or advertise cloud Develop. No new dependency, provider installation, image build, cloud resource, model request or credential import was performed. Tests use an in-process TLS HTTP fixture and temporary private journals. Their “VMs” are fixture identity records, not real Firecracker guests.

The boundary pins runtime `cf536c284434fdd2f09bbab35ec807a5dacc87e4` and accepts only the candidate AWS `m8i.xlarge` configuration, an explicit region, template/build digest, host generation, management-boundary receipt and restore receipt. These required operator attestations are not proof of account/region/KVM availability. Other provider/type combinations fail as unsupported. The configured resource/spend ceilings are enforced; actual host capacity, provider quota and price checks remain a required wiring gate. Tests deliberately exercise configured limits independently of actual instance capacity.

- **Provider protocol:** private-address HTTPS with verified TLS, no proxy inheritance, redirects or direct port5008 access; API credential only in the authenticated header. Explicit private sandbox traffic, no auto-pause/resume and outbound IPv4 denial are requested. Real Embed policy parity, IPv6 behavior, guest traffic-token/attach authentication and model-specific egress remain unverified. The allocation-only boundary starts no command.
- **Exact lifecycle:** `Allocate`, `Reconcile`, `Cancel` and `Close` bind person/instance owner, project, task, attempt, operation, source/context/bundle digests, deployment generation and immutable provider identity. One Create is sent per durably recorded attempt; retry does not resend it. A lost response requires exact metadata/identity lookup, with missing/ambiguous/paginated results retaining the charge. Cancellation during Create persists intent, drains that same request and confirms exact deletion. Shutdown cancels transports and retains the state lock until those operations settle; it does not silently destroy guests.
- **Durability and charges:** a private, exclusive local journal and an exclusive fenced `Checkpoint.Claim` writer with exact hash acknowledgement precede Create. `DirectoryStore` provides actual controller-host files, exact readback and fresh-destination/current-head restore. Its required distinct host IDs/separation receipt must be verified by wiring; filesystem tests do not prove physical host separation, power-loss guarantees or provider backup durability. Replacement-host generation mismatch retains old reservations and refuses new allocation rather than using an empty replacement inventory as absence proof. Only exact known sandbox absence releases active RAM/CPU/concurrency. Estimated spend remains charged after spin-down; actual provider/model/storage billing is always explicitly unsettled. No automatic refund, quote or provider billing cap is claimed.
- **Bounded transfer:** `WriteTransfer` and `VerifyTransfer` stream deterministic, hash-bound archives for one exact project/task/attempt/source/context and input/output direction. Payloads are limited to64MiB and4,096 files; journal/response metadata is bounded separately. Input paths are under `source/` or `context/`, returned data under `output/`. Validation rejects links/PAX, traversal, Windows special names, case/ancestor collisions, extra files, changed bytes and mismatched identity. Existing AGENTS.md/CLAUDE.md bytes are preserved as data. The initial portable contract accepts printable ASCII paths only and refuses unsupported names. It does not discover files, extract archives, execute instructions, trust model check claims, or merge output.

### Concrete controller-host durability

`NewDirectoryStore(StoreConfig)` provides private filesystem objects, not a new server or cloud service. Journal and input/output artifacts are content-addressed, hash-read back and retained within explicit byte/object budgets. `Checkpoint.Claim` grants exactly one fenced writer, matched to the current durable head and local journal; a released writer cannot publish or release a successor. Another process/store handle is excluded by the existing statelease. `RestoreController` requires the reviewed current head and a fresh destination, refuses stale/implicit/overwriting restores, and keeps unknown old-host charges. Artifacts remain available through independent controller and store reopen without re-executing a task.

The store requires distinct declared controller/runtime host IDs and a separation receipt, rejecting a declared same-host layout. **Actual physical separation is still a deployment/configuration acceptance gate**. A disk on the same replaceable host is not off-host backup merely because it has another directory. Provider-host loss/restoration and storage persistence across actual failure remain unverified. No record or artifact is silently garbage-collected to admit work; a full store refuses further publication/allocation. Archival/retention and operator recovery are still required. File readers supplied by wiring need transport deadlines because a context cannot preempt an arbitrary blocking Reader; partial copies must be discarded on error.

[Directory-store source/fixture evidence](evidence/cloud084-controller-store/README.md) supersedes the earlier mandatory-checkpoint interface-only limitation, but does not supply live cloud evidence.

## Candidate E2B runtime integration contract

1. **Named capability, explicit limits.** After gate lift and the candidate evaluation, select one concrete Embed provider/type/region and introduce its named backend capability with a pinned template/build identity containing supported upstream CLI versions and Luci's existing sandboxd transport. Verify reported CPU/memory/disk against an explicitly supported template size; refuse an unrepresentable request rather than round down. Start with fresh task execution and evidence return. Mark transparent resume/fork, arbitrary images, privileged/nested Docker, direct deploy and unvalidated regions as unsupported until individually implemented and tested.
2. **Exact project/context transfer.** Current host mounts cannot cross this boundary. Under current project authority and source exclusion, capture a bounded source snapshot/git bundle and immutable reviewed-context manifest, including project/task IDs, approved revisions, source commit/digest, required files and hashes. Exclude credentials and unrelated projects. Transfer to a new per-task sandbox; verify every byte before launch; use an independent repository, not dangling host worktree links. Preserve AGENTS.md/CLAUDE.md. Keep approved context read-only to the coding user and treat it as data, never execution or deployment authority. Missing, unsafe, oversized or mismatched files refuse launch.
3. **Keep upstream execution.** Use Luci's current harness argument and task/report contracts. E2B envd's filesystem/process API can prepare the sandbox and start sandboxd; retain the existing framed attach protocol rather than replace upstream Codex/Claude engines or present an unrelated SSE stream as that protocol. Luci's current shared dialer constructs `ws://` and `http://`; cloud attach/readiness need explicit authenticated TLS endpoints. No fallback to public unauthenticated shell traffic. Test E2B traffic-token authentication separately from Luci's attach token, including missing/wrong-token refusal.
4. **Credentials and network.** Keep the E2B control-plane key outside the guest and browser. Supply only the explicitly selected model credential through the existing scoped secret path, with approved destinations and no tokens in context, metadata, logs or exported bundles. Host ChatGPT/Claude login does not prove container or cloud authentication. Validate the actual upstream CLI login/API-key flow; no silent copying of host auth stores. Explicitly request protected sandbox traffic and verify it; pin egress policy and template capabilities instead of relying on provider defaults. Cloud data transfer/account choice must be visible before starting.
5. **Durable lifecycle and capacity.** Persist provider account/scope, exact sandbox identity, Luci instance/project/task/operation, template identity and charge before exposing success. Reserve capacity and estimated spend atomically with the operation. Use v2 idempotency only after its actual retention/feature contract is established; a timeout or expired key is not permission to create another task. Unknown creation/deletion/transport retains uncertainty and its charge until exact settlement is proved. List/reconcile only owned identities; never reap unrelated sandboxes. Enforce maximum lifetime without automatic unreviewed extensions or traffic-triggered resume. Pause is a separate capability, not completed work or released storage cost. Reconnect must attach to the same upstream execution, not replay its command.
6. **Return, review and delivery.** Retrieve bounded changed files/patch, logs, command exit evidence and task claims against the exact context and source base. Validate paths, hashes and ownership before storing. Record model claims separately from verified checks. Compare the current project head/context to the captured base; retain drift/conflicts and require reviewed reconciliation. Existing merge and deployment authority gates apply. A verified task does not imply successful whole-application checks or deployment. Cloud output returns to the same project/activity loop and amendment history.
7. **Cost and resource controls.** Show provider, region if selectable, size, duration, estimated charge, model costs and persistent-resource exclusions before explicit cost acknowledgement. Embed host/storage/network costs, actual region availability and model costs are unverified. Managed E2B service pricing is a separate alternative, not the selected host quote. Refresh the chosen account's actual prices/quotas during configuration; do not invent a low rate. A Luci budget is an admission/stop policy, not a guarantee that provider billing is capped. Keep local memory/CPU controls for transfer/indexing/UI and global fair scheduling across projects; cloud work does not justify loading four repositories fully into local RAM.

The following API capabilities are source candidates, not verified Embed deployment parity. E2B's open-source source currently documents `/v2/sandboxes` idempotency and secure envd, but managed-service/version parity remains a required preflight. SDK defaults allow outbound traffic and public sandbox URLs; explicitly select and test the intended policy. Pause/resume may retain credentials in memory/snapshots; credential retention and revocation are release gates, not an assumed benefit.

## Durable host lifecycle and elastic swarms

Before dependable hosted execution, define durable storage independent of a replaceable Embed host. Supplied AWS/GCP/Azure Terraform replacements create fresh storage. Preserve exact task/project/context/source manifests, accepted outputs and supported checkpoints; back up and validate restore before replacement, and test unexpected host loss without duplicate task execution or silent result loss. Explicitly document which running work cannot resume and how it is reconciled/replanned. Keep credentials out of exported evidence and define snapshot retention/revocation. Internal port5008 is not authenticated by the runtime; private routing alone must be paired with the selected authenticated management boundary. Do not expose it publicly.

CLOUD-088 requires the primary Luci to decompose many small tasks and allocate each upstream subagent its own newly allocated isolated microVM. Maintain separate personal Luci/team peer/task attempt/provider VM identities, a durable dependency graph and immutable task-specific context. Expose normal in-app concurrency/resource/spend policy, dynamic backpressure and priorities rather than a separate infrastructure console or a tiny hard-coded worker ceiling. Retry and reconnect preserve exact ownership/idempotency; failed or unknown Create/Delete never grants a replacement or frees a charge by assumption. Capture durable outputs before teardown, settle each owned VM and report retained storage/snapshot/model costs separately.

## Implementation and acceptance sequence — resumed after contract audit

- **A — one concrete candidate contract:** keep Docker working and cloud microVM explicitly unavailable. Complete the pinned Embed provider/type/region, KVM, private authenticated management, source/credential transfer, host-loss persistence and price/quota contract. No provider provisioning without configured access/cost authority; no generic AWS/GCP/Azure support claim from recipes.
- **B — one real cloud task:** implement the selected adapter using existing CLI/sandboxd contracts and protected transport. With actual configured access/cost policy, run an upstream model on approved context, receive native outcome/changed files, independently check and review them. Controlled fixtures are separate from live microVM/provider evidence.
- **C — elastic fan-out and failure:** CLOUD-088 depends on CLOUD-084/085/086. Use the controlling contract's representative twelve tasks/four projects/four concurrently active distinct microVMs; amend context while tasks run, reconcile conflicts, test cancellation/failure/controller restart/lost Create and observe per-VM spin-down/ownership/charge settlement. Preserve unrelated resources and all uncertain charges. Test configurable limits and fair backpressure without imposing this fixture's concurrency as a product ceiling.
- **D — live delivery and team loop:** route real accepted source through checks, review, preview and actual policy-permitted application deployment. Two people's Lucis coordinate accepted revisions and affected implementation/delivery; genuine contradictory intent is surfaced. A sandbox URL or saved shared draft is not completion.
- **E — operational recovery:** verify host loss/replacement, backup/restore, upgrades, pause/resume limits, credential revocation, provider outage, unknown allocations and cost accounting. No turnkey reliability claim from Terraform or snapshots. Local resource and responsiveness acceptance still applies to transfer/indexing/UI.
