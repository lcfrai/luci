# Installed runtime pull gate (source, not installed evidence)

This is the fixed read-only gate for [LOCAL-041 v2](../../../docs/luci/LOCAL-RUNTIME-PULL-V2-RECONCILIATION-2026-10-14.md). Release production builds it as a static Linux amd64 binary from the complete clean Git subtree here, verifies the version output `luci-registry-gate 1`, and places it with pinned Distribution 3.0.0 in the small tagless scratch bootstrap image. It never builds or fetches an image on the customer's PC.

The consumer mounts the verified store and its generated `runtime-pull-allowlist.json` read-only at `/registry-data`, and writable private tmpfs at `/run/registry`. Only these fixed environment values are accepted: `LUCI_PULL_ALLOWLIST_SHA256=<64 lowercase hex>`, `GOMEMLIMIT=32MiB`, `GOMAXPROCS=1`. Start `/luci-registry-gate` with no arguments. The separate `/luci-registry-gate --version` probe has no mount or environment prerequisite. The image config fixes user `65532:65532`, workdir `/`, entrypoint `/luci-registry-gate`, exposed `5000/tcp` and empty image environment; the consumer sets the three values at container creation, not in image history.

The maintainer builds the static `luci-registry-gate` with `CGO_ENABLED=0 GOOS=linux GOARCH=amd64 go build -trimpath -buildvcs=false -o luci-registry-gate .` from this subtree and verifies `--version` before packaging. The same private build context contains only this binary, the separately hash-verified pinned native Distribution 3.0.0 `registry` executable, and this Dockerfile. The producer records the exact Dockerfile SHA-256 as `buildRecipeSHA256`, the complete clean Git subtree digest as `gateSourceSHA256`, and the resulting config/layer/archive bytes in its bounded bootstrap receipt. No package consumer builds from this recipe.

The hash-bound allowlist has exactly `version:1`, `repository:"luci/runtime-installed"`, `manifestDigest`, `manifestBytes`, `configDigest`, `configBytes`, and `layers:[{digest,bytes}]` in manifest order. All digests include `sha256:`. It is generated only from the already verified v2 package; the gate refuses unknown/duplicate fields, duplicate layer digests, sizes above the v2 bounds, or a changed allowlist file. Frontend `0.0.0.0:5000` is published only as host `127.0.0.1:<owned-port>` on a fresh dedicated user bridge. Distribution is spawned at container-loopback `127.0.0.1:5001` with fixed filesystem-only, read-only configuration and `GOMEMLIMIT=96MiB`, `GOMAXPROCS=1`; it is not exposed on the bridge. The bridge itself permits egress, so the gate and Distribution must retain no fetch/proxy/redirect feature or provider credential.

The gate permits `GET`/`HEAD /v2/` and exact digest-addressed manifest/config/layer requests only. It constructs its own fixed backend URL, forwards only a bounded single `Range`, rejects authorization, request bodies, query/fragment/encoded paths, writes, backend redirects and changed content lengths/digests, and copies responses with backpressure. No Docker socket or push capability is present. The app must prove both host and selected-daemon reachability before an owned pull. Gate shutdown/child exit is not an engine retirement receipt; the app retains unknown pull outcomes and allocations until exact readback or supported selected-engine retirement.

Offline focused checks: `GOWORK=off go test ./...` from this directory. Use a clean pinned Go toolchain and build with `CGO_ENABLED=0`; no dependency download is required. Source fixtures do not establish Docker Desktop routing, helper memory use, runtime image pull or host reserve behavior.
