## Finite acquisition and offline validation sequence

1. **Pin the two missing upstream package receipts first.** Obtain a signed Debian package-index entry that gives SHA-256 for the already selected `fonts-noto-cjk_20240730+repack1-1_all.deb` URL/56,674,044-byte wrapper; record the signed index identity. Select one immutable `poppler-utils` package/dependency set with original grants for the independent standard reader. Read-only local candidate metadata is `poppler-utils 25.03.0-5+deb13u4`, `/usr/bin/pdftotext` SHA-256 `7fe3559cac3ba61dd93650a1ba90499b9fc488184ef8d0f2f1305ddf52c0378b` and `/usr/bin/pdftoppm` SHA-256 `f22d753dfb4c31c9f0198d608982dac5b06a3c5d9a08d7d9bf0c6004f08a1a56`. Those are **observed binaries, not a portable package/dependency receipt**. Do not invoke them as an assumed host fallback.
2. **Acquire only the nine selected archives after separate approval:** the one exact Go 1.25.0 archive for the chosen OS, the one pinned Debian CJK wrapper, and seven selected module ZIPs from `inputs-v1.json`, plus exactly their `.mod`, `.info` and original grant files. A task-owned `pdf-inputs-<32 hex>` directory records each URL, byte cap, SHA-256 and final durable file identity. Refuse redirect to a different host, changed bytes, extra input or partial publication. No Go/toolchain/font input already installed on the host silently satisfies this step.
3. **Validate offline under the same hard-owned process limits.** The bounded `preflight.py` verifies exact Go archive bytes, staged font/copyright hashes, module ZIP path/count/expanded bounds and each Go ZIP `h1` plus separate `.mod` `h1`. Bounded ar/tar extraction must then prove that the exact staged font and copyright came from the wrapper whose signed SHA was pinned; the current preflight does not yet make that relation. Stop if wrapper metadata or extraction proof is missing. Generate a **private** `go.sum` from the verified ZIP and `.mod` h1 pairs; do not edit the repo module or production `go.mod`.
4. **Close the actual package graph before build.** From a private copy of this pilot module, use the exact verified Go toolchain with `GOTOOLCHAIN=local`, `GOWORK=off`, `GOSUMDB=off`, `GOPROXY=file://<owned-verified-proxy>`, task-owned caches and `go list -mod=readonly -deps -json .`. Retain package/module/version digests and every selected original grant. The only permitted external modules are the seven manifest entries. An extra package, missing module metadata, changed `go.mod`/`go.sum`, implicit network request or unavailable licence stops the run. Build this module only with `GOPROXY=off`, `CGO_ENABLED=0`, `-p 1`; do not build the product or invoke a downloader from the pilot.
5. **Render one fixed page.** The reviewed private SDK owner must hold the exact cross-worker lock and fresh host reserve plus a full 512 MiB charge. A separately owned attempt starts the verified binary in a selected immutable image with `Memory=MemorySwap=536870912`, `NanoCPUs=1000000000`, `PidsLimit=32`, `NetworkMode=none`, no privilege/capabilities, read-only root and only exact read-only inputs plus its private writable stage. Compare the effective inspect response and original image/CID/labels/mounts before Start. Enforce a 30-second render deadline. `main.go` limits its bounded font read and original font + CFF subset + PDF buffers together to 32 MiB; final PDF is at most 16 MiB. Library allocations remain covered by the hard container cap. An OOM, timeout, cancellation or uncertain SDK response is a failed/unknown owned attempt, never a PDF success.
6. **Verify and retire.** Run `verify_pdf.py` from the same exact stage under bounded ownership, then an independently pinned standard reader must extract **exact `日本語`** and render exactly page 1 at fixed resolution into a bounded private image for visual glyph inspection. The Poppler candidate above cannot be used until its own dependency/grant and bounded-execution receipts are closed. The controller records PDF/font/input hashes, reader output, host/cgroup peaks, elapsed time and exact positive process/container/reader retirement before releasing the live OS lock or removing only its own stage. Ambiguous exit, missing output, partial reader data or failed receipt publication retains the durable lease/charge and stage identity for readback even if the process dies and the OS lock is released. One CJK pilot cannot enable general PDF export.
