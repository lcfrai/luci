# Phase W task scopes: tasks 81 to 100 (W2's digest and HTTP, W2's desktop and proof, W3's Hub)

Scope paragraphs for tasks 81-100 of `2026-09-25-phase-w-work-layer.md`: the digest builder and
mail seam (81), W2's `hubclient` over HTTP and its end to end (82), W2 on the desktop (83-96),

**Conventions used below.**

- Paths are relative to the repository root; desktop paths are under `desktop/`. A path marked ⚑
  is shared (skeleton *File map*): the tasks that touch it run in task order, never in parallel
  worktrees. Hub server paths (`server/`, `store/`, `migrate/` under
  `control-plane/internal/hub/`) are planned by the Hub plan and **UNVERIFIED until they land on
  `feat/hub`** (rule H1); sibling-plan paths (Phase T) are **UNVERIFIED until merge** (rule H2).
- "05 §x" is `docs/superpowers/planning/2026-09-25-linear-parity/05-design.md` (revision 2);
  "L-n" is row n of the parity matrix in `01-linear-feature-inventory.md` as 05 §1 prices it. A
  row a task **closes** is built there and counts only when the task's acceptance commands pass;
  a row it only **serves** names the task that closes it; a row closed jointly names every task.
- Seams are the skeleton's `SW.n` (*Seams* table). `SW.18` is the W2 wire (`WorkPlan`, task 72);
  `SW.19` is the W3 records (task 99). Every surface test calls `expectNoPrediction(container)`
  (SW.8) and reads its data through the replica (SW.16).
- "Mutant" names the one wrong implementation a test exists to kill.
- Go tests run as `go test ./control-plane/... -race -count=1`, Hub integration rows with
  `-tags integration` against `control-plane/cmd/hub/compose.yaml`; desktop tests as
  `npm --prefix desktop test` and `npm --prefix desktop run typecheck`.
- Every desktop task follows the skeleton's *Global constraints*: list-focus keys only, one
  heartbeat clock, `tabular-nums`, `transform`/`opacity` motion only, Commit Mono facts at
  `--t-fact`, no Hub text on disk (ADR-H1). `OD-27`: no surface shows a prediction, a forecast, a
  target line or a percent-complete; `OD-28`: Commit Mono and Segoe UI Variable.

**81 — the digest builder and the outbound mail seam.** The Hub side of 05 §5.4 W2's *"the digest
(desktop and email)"*, held to AX §6 item 8 (*"Notifications are a digest, never a stream"*,
`docs/AGENTIC-UX.md:171`) and AX §10 anti-pattern 8 (*"No more than 1 notification per user per 15
minutes"*, `:243`). **Files:** `control-plane/internal/hub/server/work_digest.go` and
`store/work_digest.go` (the builder and its read route; the file map's *one pair per aggregate*
row), new `control-plane/internal/hub/mailer/{mailer,graph,fake}.go`, `server/janitor.go` ⚑ (one
digest-send step, after task 77's cycle steps, in task order), `server/matrix_integration_test.go`
⚑, and `cmd/hub/config.go` ⚑ for `PANACEA_APP_HUB_MAIL_*`. **Interfaces:** `mailer.Mailer
{ Send(ctx, Message) error }` with `Message{To, Subject, Text, HTML, IdempotencyKey}`; `graph.go`
sends through Microsoft Graph `sendMail` under the Hub's workload identity, because the contract
says *"No variable holds a secret in any deployed environment"* (hub-contract §12.2, `:2151-2152`
on `feat/hub` at `48351f8`); `fake.go` records messages for tests. The builder is a **pure
function** `BuildDigest(events []hubapi.Event, subs Subscriptions, since time.Time) Digest` over
the change feed's Work kinds (SW.5, task 13) and SW.18's W2 kinds (task 72): issues you are
subscribed to that changed, changes in views you subscribe to (L-96), due-soon issues (L-37),
deferred items coming due, each as `DigestItem{subject, alias, title, cause, at, link}` where
`link` is task 80's https Hub link. It reads the per-person `DigestSettings{email: off·hourly·daily}`
and the defer record from SW.18; **if task 72's part does not carry them, that is a gap to close in
72, not here**. Route: `GET /v1/work/digest?since=` (member of the team; a person reads only their
own). **Tests first:** the builder returns one digest for 40 events on one issue (mutant: one item
per event, the firehose AX forbids); a second send inside 15 minutes is refused by the sender
(mutant: the rate limit is per issue, not per person); a digest never carries a description,
comment or request body, only the head's title, alias, cause and link (mutant: the revision's
description is rendered into the mail); an event the person cannot read never enters their digest
(mutant: filtering by team instead of by project read, hub-contract §7.11); the janitor step is
idempotent across two replicas under the advisory lock (mutant: both replicas send, `-tags
integration`); `graph.go` is tested against an `httptest` server only. **Depends on** 13 (feed
kinds) and 74 (the W2 tables). **Closes** L-116's email half jointly with 94 (the desktop half);
its Teams half is task 165. **Serves** L-37, L-96 and L-117 (closed by 89, 91 and 94, and W1's
task 13). **Does not claim:** that Graph `Mail.Send` is granted to the Hub's identity in any
tenant (**UNVERIFIED**; an owner or tenant-admin act), inbound mail (task 149), or that an issue
title may leave the Hub in mail at all (no owner ruling yet; the part records the question).
