# LOCAL-041: compressed runtime pull contract (14 October 2026)

**Status: architecture and producer/consumer schema for root audit and Windows producer ACK. No pull, helper, Docker, or cloud effect is authorized by this document alone.** This supplements the [v1 Docker-save contract](schemas/RUNTIME-OCI-MANIFEST-V1.md); it does not reinterpret v1 archives or erase their original failed-run evidence. The normal installed route selects only a complete, verified v2 package. Missing or invalid v2 assets refuse with an actionable setup status; neither v1 `ImageLoad` nor the advanced source build is an implicit fallback.

## Why the transport changes

At pinned Moby 28.5.1 (`f8215cc266744ef195a50a70d427c345da2acdbb`), classic `ImageLoad` first untars the *whole* save archive to daemon temporary storage (`image/tarexport/load.go:46-54,114-128`). The source-sized LOCAL-041 admission correction is truthful but cannot by itself establish a usable low-memory install. The classic pull path instead downloads each compressed layer to a `GetImageBlob` temporary file, verifies its compressed digest, and decompresses/registers that layer (`distribution/pull_v2.go:169-304,867-869`; `distribution/xfer/download.go:318-355`). It does **not** make the daemon's guest cache or concurrent temporary files disappear. Its cancellation path stops retries, but lost transport still leaves an uncertain effect. Docker's default loopback registry exception (`registry/config.go:167-171`) does not prove that a Windows host-published port is reachable from the selected Docker Desktop daemon.

## Exact normal package and source proof

The portable/native release carries **one** copy of each regular, nonlinked member below, bound by the outer release manifest/hash and `runtime/source-receipt.json` (`version:1`, exact clean 40-hex source commit, explicit `sourceDirty:false`). The embedded Linux management core uses an exact source-bound companion marker and transfer; it must not duplicate the large payload.

`runtime/runtime-source-reuse-v1.json` and its exact prior manifest/build-receipt siblings are included **only** when equivalent-input reuse is claimed; their existing v1 byte/hash contract remains mandatory. No v1 large archive is duplicated in the ordinary v2 package. The producer may retain v1 diagnostics and the explicit advanced v1 release separately; a v2 failure never switches transports.

The producer retains the **original runtime config bytes** (`sha256(config)=image.id`) and ordered original uncompressed diffIDs. It builds a Docker schema-2 manifest for the same config, records every compressed layer digest/size and verified uncompressed diffID/size, and stores those exact blobs in the pinned registry layout. No flattening, relabeling, foreign blob URL, mutable external tag, or arbitrary Docker endpoint is accepted. The producer's original source-bound build receipt and an exact conversion/push receipt bind the new compressed representation. Equivalent runtime inputs across a later UI/documentation commit require the existing independently verified `runtime/runtime-source-reuse-v1.json` and exact original byte receipts; changing `sourceCommit` text alone cannot authorize reuse. No downloaded source, registry blob, helper binary, image, or secret is fetched during ordinary install.

The importer verifies package identity, source/reuse evidence, every registry-store member and compressed blob, decompressed diffIDs and original config **before** the first Docker effect. It extracts to a fresh private owned data directory on the selected storage volume using bounded streaming, with complete member/path/count/expanded-byte limits and held regular-file handles. It verifies the small bootstrap archive independently. The helper mounts only the verified store read-only; it receives no Docker socket, credentials, host network, privilege, or general outbound route. Pinned Distribution serves the selected immutable manifest/blob bytes in read-only mode behind a small static Go gate that allows only the one fixed repository, digest and GET/HEAD operations. The gate denies foreign paths, redirects, uploads and mutable publication. Its soft Go memory targets are 32 MiB for the gate and 96 MiB for Distribution; the **proposed** helper cgroup hard cap is 256 MiB, subject to source tests and actual measurement, not a claimed pass.

The application owns bootstrap load, a fresh dedicated user bridge, the exact helper container and private directory, and a published **host `127.0.0.1` port only**. Before pull it proves both host and selected daemon reachability to that exact helper, selected engine/instance identity, loopback registry behavior and current actor/resource authority. Unsupported remote engines, filesystem backing, or daemon-loopback routing refuse explicitly. No `host.docker.internal`, daemon-wide insecure-registry/trust edit, default bridge, LAN listener, downloaded image, user-operated registry or old large producer image is substituted. Pull by immutable manifest digest; inspect exact resulting config ID, ordered diffIDs and runtime configuration before an allocation-labelled derivative and tag publication under the existing journal and publication lock. The shared payload is not allocation-owned cleanup.

## Admission and recovery

Bootstrap `ImageLoad` has its own small, measured admission and exact engine journal. For the main pull, the conservative simultaneous host claim is at least **all verified final uncompressed layer bytes + all compressed blob bytes that Moby could retain as temporary files + the 256 MiB helper hard cap + 512 MiB daemon bookkeeping**, rounded up to MiB, with existing worker claims and host reserve/margin applied by the normal admission system. Keep the 1 GiB worker/CPU policy, full Docker inventory and 100 ms host watch. Count all compressed bytes until a positive terminal/readback proves a narrower lifetime; serial GET delivery alone does not prove serial extraction. A future reduction requires source- and test-supported Pull-complete/Already-exists or parent-order proof, followed by measured installed behavior. Neither helper cgroup limits nor the admission estimate cap daemon page cache. A queued/refused install leaves the app and planning usable and shows the specific capacity requirement.

Journal separate bootstrap, helper, registry readback, pull, derivative, tag and retirement effects with exact source, engine/instance, repository/manifest, actor/allocation and generation. A lost pull response, cancelled stream or helper death is **unknown** until exact config/diffID/tag and terminal transfer readback or positively retired executor generation settles it. No retry creates a second helper/pull around an uncertain first effect. Positive owned helper stop/absence, private-directory retirement and retained resource charge are distinct from image publication. No absence-only lease clearance or deletion of shared/unrelated images, containers or storage. The v1 archive/source route remains explicitly selectable only as its existing advanced/diagnostic path under its own conservative admission and journal.
