# C032 v2 headers-only controlled transport proof

One v2 browser attempt passed 18 checkpoints. These are checks of the new headers-only mechanism, not cumulative unique checks combined with the earlier 18-check full-body proof or the failed pre-body proof. Both previous proof manifests and all their listed payload hashes were verified unchanged before and after this attempt. No installed application or main performance diagnostic ran.

The exact frozen original Playwright context.route handler stayed active. Its source is bound to idle actual/sustained.mjs SHA256 18429d2a6497cfec582c8565b572b3ca567b756f2f9d403efd79b6b405719dc2. A transparent wrapper counted calls and enforced the tiny proof's request cap; every actual request reached the unchanged handler. Its same-origin restriction, closing/fixtureError/workflow-failure refusal, and mutation logging coexisted with a separate CDP Fetch response-stage session. Baseline and defer used the same mechanisms.

CDP requested no response body and created no body-capture promise. Only successful 200 GETs on the exact overview/scheduler paths were eligible for header-delivery holding. Each deferred checkpoint recorded an unresolved browser fetch with an original paused response ID. Release used Fetch.continueResponse with only requestId. The page's ordinary fetch read the body after release, and its status, complete exposed headers, and UTF-8 body matched the original loopback server response exactly. Each eligible original request reached the server and route guard once. No replacement response, fulfillment, route.fetch, or replay was used.

403, POST and wrong-path responses were continued immediately and never held. The original handler logged the POST and rejected cross-origin, closing, fixtureError and workflow-failed requests before the server. In the affected pre-body case, the server flushed response headers but withheld the body. The page's AbortController produced AbortError and Network.loadingFailed with the exact paused network ID, canceled=true and net::ERR_ABORTED. Only after that correlation, bounded Fetch.continueResponse was attempted and returned Invalid InterceptionId, confirming the naturally canceled interception was already terminal. That protocol error is accepted only for the exact correlated cancellation. The original target reached server/guard once, the server wrote zero body bytes, and its response closed without finishing. No upstream-completion or backend-work-preservation claim is made.

There were 12 browser requests and 10 response pauses, with a maximum declared body size of 133 bytes and maximum pause of 35.74 ms. Caps were 16 requests/pauses, 64 KiB declared body, 1 second per pause, 600 ms continuation and 88 seconds hard process lifetime. Overflow branches were not fault-injected. Passing evidence comes from capture-free pause/release/delivery/cancellation checkpoints, not an inferred performance threshold.

All pending interception IDs were settled before Fetch was disabled or Chromium closed. The separate CDP session was disabled/detached, owned Chromium and loopback server closed, owned profile removed, and no owned browser PIDs remained. Frozen source/runner/prior evidence hashes were unchanged. COMMANDS.json records the exact command and observed exit; attempt-1.log retains original merged stdout and stderr. Source snapshots, original result and chronological raw events are preserved.

Interpretation is limited to response availability, including possible transfer/backpressure and scheduling effects. This does not isolate frontend commit causality, establish full application readiness, or authorize an installed diagnostic.
