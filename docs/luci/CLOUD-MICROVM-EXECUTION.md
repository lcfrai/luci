# Cloud microVM execution: reuse decision and implementation contract

Status, 11 October 2026 UTC: **CLOUD-084 is an open P1 implementation gap. E2B Cloud is the proposed first microVM provider, not an implemented or verified Luci backend.** Local Develop continues to boot the existing upstream coding harnesses in Docker. An SSH-connected Docker host is a remote container host; it must not be presented as microVM isolation.

Luci owns context, environments, coordination, review and delivery. Codex, Claude Code and other explicitly supported upstream tools remain the coding engines. Discover and Design create and amend context; Develop consumes the exact approved version; changes and checks return for review; Deploy uses reviewed source and evidence. Standalone export/return is secondary interoperability, not a replacement for integrated Develop.

## What is implemented

`control-plane/internal/backend/backend.go` exposes Create, Get, List, Attach, Destroy and Close. The working default is Docker. Session creation supplies a host worktree, reviewed context and conversation mounts plus a working directory. The Kata adapter explicitly rejects Mounts and WorkDir and describes itself as dormant. Configuring `LUCI_BACKEND=kata` therefore does not deliver the current task workflow.

The existing catalogue enables Codex, Claude Code, OpenCode and Shell; availability of a CLI is distinct from a configured model connection and successful real-provider execution. No cloud microVM provider is supported by this revision. Do not offer E2B, Fly, AWS or Azure as interchangeable working execution choices. Existing remote workspace/provisioning capability is not evidence of microVM task execution.

## Reuse decision

| Candidate | Official-source evidence | Fit and boundary |
| --- | --- | --- |
| **E2B Cloud — first implementation candidate** | E2B's Apache-2.0 runtime describes one Firecracker microVM per sandbox. Its API supplies create/read/list/delete, bounded lifetime, pause/resume, metadata, metrics, protected traffic and process/filesystem services. The pinned v2 create contract describes idempotency with explicit mismatch, in-progress and unknown outcomes. | Reuse the managed runtime and existing Luci upstream CLI/sandboxd contracts. Implement project transfer, authenticated cloud transport, exact ownership and durable return evidence. Verify API feature availability against the actual account/deployment; repository source is not a managed-service acceptance result. |
| **Fly Machines — credible alternative** | Official docs describe VM lifecycle, OCI-image roots, resource selection and a REST API. Suspend uses Firecracker snapshots. The official `fly-go` client is Apache-2.0 and carries machine instance/version identifiers, leases and lifecycle operations. | Good fit for Luci's existing image and Go control plane. Requires explicit project transfer, private connectivity, persistence, image publication and app/region management. A stopped machine is not deleted; root filesystems and volumes have separate billing/persistence. Do not assume a suspend snapshot survives a cold start. Not a second supported provider. |
| **E2B Embed — later BYOC reuse** | The same Apache-2.0 runtime supplies single-node Compose and AWS/Azure/GCP deployment recipes. The Compose guide requires Linux/KVM; AWS recipe selects a nested-virtualization-capable instance; Azure has its own instance/prerequisite contract. | Reuse rather than build a hypervisor. This is a whole runtime stack on a KVM host, not a cheap generic Docker VM. Actual account permissions, instance/region availability, nested virtualization, storage, backup, TLS and cost remain unverified. Do not turn these recipes into claims that Luci supports those clouds. |

E2B runtime and SDK source licences were read and match Apache-2.0. Fly's client/docs licence was also read. Preserve notices for adopted components. These licences do not license the hosted service, every transitive dependency, or proprietary upstream coding tools. Their terms and billing remain separate. Local testing relayed Glasses discovery of E2B, firecracker-containerd and Rivet's sandbox-agent; this cloud review independently checked E2B and Fly official sources, not those two additional implementations. No Glasses call, dependency adoption, installation or provider provisioning occurred in this review.

## First E2B implementation contract

1. **Named capability, explicit limits.** Introduce one E2B backend capability with a pinned template/build identity containing supported upstream CLI versions and Luci's existing sandboxd transport. Verify reported CPU/memory/disk against an explicitly supported template size; refuse an unrepresentable request rather than round down. Start with fresh task execution and evidence return. Mark transparent resume/fork, arbitrary images, privileged/nested Docker, direct deploy and unvalidated regions as unsupported until individually implemented and tested.
2. **Exact project/context transfer.** Current host mounts cannot cross this boundary. Under current project authority and source exclusion, capture a bounded source snapshot/git bundle and immutable reviewed-context manifest, including project/task IDs, approved revisions, source commit/digest, required files and hashes. Exclude credentials and unrelated projects. Transfer to a new per-task sandbox; verify every byte before launch; use an independent repository, not dangling host worktree links. Preserve AGENTS.md/CLAUDE.md. Keep approved context read-only to the coding user and treat it as data, never execution or deployment authority. Missing, unsafe, oversized or mismatched files refuse launch.
3. **Keep upstream execution.** Use Luci's current harness argument and task/report contracts. E2B envd's filesystem/process API can prepare the sandbox and start sandboxd; retain the existing framed attach protocol rather than replace upstream Codex/Claude engines or present an unrelated SSE stream as that protocol. Luci's current shared dialer constructs `ws://` and `http://`; cloud attach/readiness need explicit authenticated TLS endpoints. No fallback to public unauthenticated shell traffic. Test E2B traffic-token authentication separately from Luci's attach token, including missing/wrong-token refusal.
4. **Credentials and network.** Keep the E2B control-plane key outside the guest and browser. Supply only the explicitly selected model credential through the existing scoped secret path, with approved destinations and no tokens in context, metadata, logs or exported bundles. Host ChatGPT/Claude login does not prove container or cloud authentication. Validate the actual upstream CLI login/API-key flow; no silent copying of host auth stores. Explicitly request protected sandbox traffic and verify it; pin egress policy and template capabilities instead of relying on provider defaults. Cloud data transfer/account choice must be visible before starting.
5. **Durable lifecycle and capacity.** Persist provider account/scope, exact sandbox identity, Luci instance/project/task/operation, template identity and charge before exposing success. Reserve capacity and estimated spend atomically with the operation. Use v2 idempotency only after its actual retention/feature contract is established; a timeout or expired key is not permission to create another task. Unknown creation/deletion/transport retains uncertainty and its charge until exact settlement is proved. List/reconcile only owned identities; never reap unrelated sandboxes. Enforce maximum lifetime without automatic unreviewed extensions or traffic-triggered resume. Pause is a separate capability, not completed work or released storage cost. Reconnect must attach to the same upstream execution, not replay its command.
6. **Return, review and delivery.** Retrieve bounded changed files/patch, logs, command exit evidence and task claims against the exact context and source base. Validate paths, hashes and ownership before storing. Record model claims separately from verified checks. Compare the current project head/context to the captured base; retain drift/conflicts and require reviewed reconciliation. Existing merge and deployment authority gates apply. A verified task does not imply successful whole-application checks or deployment. Cloud output returns to the same project/activity loop and amendment history.
7. **Cost and resource controls.** Show provider, region if selectable, size, duration, estimated charge, model costs and persistent-resource exclusions before explicit cost acknowledgement. E2B's current managed prices/quotas were not retrievable in this network environment, so there is no verified quote here. Refresh the account's actual price/quota information during configuration; do not invent a low rate. A Luci budget is an admission/stop policy, not a guarantee that provider billing is capped. Keep local memory/CPU controls for transfer/indexing/UI and global fair scheduling across projects; cloud work does not justify loading four repositories fully into local RAM.

E2B's open-source source currently documents `/v2/sandboxes` idempotency and secure envd, but managed-service/version parity remains a required preflight. SDK defaults allow outbound traffic and public sandbox URLs; explicitly select and test the intended policy. Pause/resume may retain credentials in memory/snapshots; credential retention and revocation are release gates, not an assumed benefit.

## Implementation and acceptance sequence

- **A — truthful capability and transferable context:** name E2B as unavailable/proposed, keep Docker working, define the provider-neutral source/context transfer and return receipt, validate bounds/isolation and retain exact local contracts. No public provisioning UI that suggests a working backend.
- **B — one real cloud task:** implement the E2B adapter, protected template/transport, provider configuration and cost acknowledgement. Run one real upstream CLI on approved project context; receive its changed files, native exit and independent checks; review/import without changing another project. Access, model credentials and actual spend are prerequisites to this live check, not to code development.
- **C — failure and four-project acceptance:** lost Create response, cancellation before/after launch, permission revocation, controller restart, expired lifetime, provider outage, paused/unknown allocation, source drift, conflicting return, two controllers and unrelated sandbox preservation. Prove no duplicate launch, correct charged capacity, fair progress, durable context and bounded local resources. Reconcile provider inventory with Luci's ledger before calling cleanup complete.
- **D — reviewed preview/deploy/amend:** route accepted source through the existing checks, preview and deployment gates; amend Discover/Design and run again without silently replacing earlier evidence. Public deployment uses its own credential/cost approval; an E2B sandbox URL is not automatically the user's production deployment.
- **E — BYOC only after the first backend works:** evaluate a pinned E2B Embed deployment on one concrete provider/type/region, with actual KVM, backup/restore, upgrades, cost and lifecycle evidence. No custom hypervisor or generic multi-cloud promise is required to establish the first supported path.

This review is source research and a reviewable implementation contract. It is not a live microVM, provider-quality, Windows, latency, billing or deployment pass. Local integrated real-provider acceptance remains the immediate delivery path while this cloud capability is implemented.
