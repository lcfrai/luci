# Ordinary packaged runtime import: source handoff

The core source implementation was published at `d929ce80d8c07df59477774926bfd9f46277c91d` on `codex/runtime-oci-import-20261014`, based on `b61b7bc4368aed2bee2fe159ea78f3b3b8e85718`; the dedicated runtime-grant and strict clean-receipt follow-up is `3a8dfdadd7f45556274e45de399ab122b393e4eb`. This is LOCAL-033 source implementation, not an installed runtime or local Docker acceptance result. LOCAL-034's earlier engine-retirement recovery remains separate.

`POST /v1/setup/runtime/install` defaults to `mode=packaged`. `mode=advanced-build` explicitly selects the retained capped source builder. The ordinary path reads only the fixed installed `runtime/` bundle and sibling `licenses/` tree. Missing or mismatched assets refuse before Docker mutation; there is no automatic source-build fallback. The package's exact `source-receipt.json` has `version=1`, a clean 40-hex `sourceCommit`, and `sourceDirty=false`. Existing packaging must still bind this receipt, manifest, build receipt and one outer archive by hash and stage its required companion consistently.

The verifier at `control-plane/internal/runtimeoci/bundle.go` bounds metadata and archive reads, rejects linked package paths and extra runtime licence/source/archive members, verifies exact source and producer receipts, config/layers and a tagless archive, and checks equal-input reuse against the original manifest and build receipt bytes. Runtime grants are exhaustive only within `licenses/runtime-image/`; the outer package verifier owns unrelated app/API/frontend licences. The clean source receipt requires literal `sourceDirty=false`, not `null` or an omitted field. `control-plane/internal/backend/dockerbe/runtime_image_import.go` rechecks the held archive descriptor immediately before `ImageLoad`; it verifies the shared immutable image before creating a metadata-only allocation derivative and before publishing the configured tag. It issues no local Go, apt or npm `RUN` on the ordinary path. The old hard reserve, engine identity, current administrator authority and fresh shared-capacity checks remain.

`control-plane/internal/api/runtime_install_execution.go` and `execution_runtime_image_leases.go` journal import, imported-only, derivative and publication phases separately. Lost daemon acknowledgments retain the exact charge and do not replay mutations. A confirmed import interrupted before derivative can release only its own unstarted reservation on restart; a running or uncertain derivative still requires exact reconciliation. The shared payload is never treated as allocation-owned. Source and setup entry points are `control-plane/internal/product/runtime_install.go` and `control-plane/internal/runtimeinstall/runtime.go`.

Focused offline checks passed with Go 1.26 and `GOMAXPROCS=1 GOMEMLIMIT=512MiB`, `go test -p 1`: `./internal/runtimeoci` (bundle/source/reuse/refusals), `./internal/backend/dockerbe -run '^TestRuntimePackaged'` (tagless load/readback, metadata-only derivative), `./internal/api -run '^TestPackagedRuntime'` (phase/restart/revocation), and affected `./internal/product -run '^TestRuntimeInstaller'`. Separately, the already requested Azure `TestAzureWorkspace(RequestGate|PreviewGate)` and `scripts/azure-setup/test_installer.py` passed before this runtime edit; these are SETUP-02-R2 source checks, not live connection proof.

This source checkpoint does not establish a working local image or model inference.
