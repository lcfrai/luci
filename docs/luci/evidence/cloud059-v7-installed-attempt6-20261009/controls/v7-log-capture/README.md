# Private controller stderr capture (external diagnostic only)

API: `createControllerLogCapture({path, expectedSession: () => session?.id, onFailure, onRelay})`. Create before acquiring the controller, attach exactly once to its fresh paused stderr pipe immediately after ownership registration, then call `settle(2000)` after controller shutdown. The settlement argument is 1–3000 ms. The function returns a failed snapshot for an incomplete/error stream; it does not signal any process. The parent helper must treat `passed: false` as a failed diagnostic and continue independent cleanup.

The module exports `projectAttachRelayLine` for the same pure projection contract. Its three aliased builtin imports and all function/constant bytes may be inlined unchanged in the launcher. Production logs `attach relay ended` at INFO only when RelayHooked returns an error; configure `LUCI_LOG_LEVEL=info`. Missing matching rows do not demonstrate successful transport.

The raw log is PRIVATE. A canonical, owned, private parent is required. The new file uses exclusive/no-follow append creation, ordinary-single-link identity checks and mode 0600. Only the first 256 KiB is retained; all subsequently observed byte chunks are drained and hashed. Overflow, incomplete prefix, oversized lines (16 KiB), or more than 16 exact-session relay rows fail capture explicitly. Do not publish the raw log: it may contain credentials, host paths and arbitrary error text.

Only finite relay projection fields, byte lengths, hashes and fixed text-classification flags are public. Socket reasons, URLs and raw errors are never exported. This is a textual observation, not proof of error causality. Exact current session selection prevents unrelated rows from entering the public projection. Quoted websocket reasons cannot manufacture context-cancel/EOF flags.

A complete observed-stream hash requires the stream end event, no stream error and complete byte-chunk coverage. EOF/close/timeout and omitted observation remain explicit. A later event after a settlement timeout cannot erase failure; the returned settlement snapshot is the state at that bounded attempt. `closed` means retention was disabled after close was attempted: it is NOT independent descriptor-closure proof; a failed close adds `private_file_close_failed` and prevents a pass. File/parent sync and identity failures are separately retained. Synchronous filesystem operations are cooperative, not preemptible by the JavaScript timer; the independent outer watchdog is still required for a hard process bound.

Validation: 17 builtin-Node inert tests passed in one recorded run, with disposable private files and PassThrough streams only. No application, browser, provider, daemon or process signal was exercised. The retained test title mentioning an already-flowing stream also tests duplicate attachment and budget refusal; do not infer an executed flowing-stream case solely from that title. Current source/log bindings were captured after the run; no independent pre/post source manifest was taken. No before-fix failure is claimed.

Reproduce only these inert controls: `node --max-old-space-size=64 --test --test-concurrency=1 controller-log-capture.test.mjs`. Original stdout/stderr are retained unchanged. Passing capture tests do not establish installed relay diagnosis or cleanup.
