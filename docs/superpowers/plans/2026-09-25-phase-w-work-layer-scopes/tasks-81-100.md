# Phase W task scopes: tasks 81 to 100 (W2's digest and HTTP, W2's desktop and proof, W3's Hub)

Scope paragraphs for tasks 81-100 of `2026-09-25-phase-w-work-layer.md`: the digest builder and
mail seam (81), W2's `hubclient` over HTTP and its end to end (82), W2 on the desktop (83-96),
W2's proof (97), and W3's first three tasks: the Phase T delta (98) and the W3 Hub wire and
migration (99, 100). A part writer reads one paragraph and the skeleton's row; where they
disagree, **the row's id, dependsOn and seams win** (skeleton, *Task scopes*) and this paragraph
is corrected.

**Conventions used below.**

- Paths are relative to the repository root; desktop paths are under `desktop/`. A path marked ⚑
  is shared (skeleton *File map*): the tasks that touch it run in task order, never in parallel
  worktrees. Hub server paths (`server/`, `store/`, `migrate/` under
  `control-plane/internal/hub/`) are planned by the Hub plan and **UNVERIFIED until they land on
  `feat/hub`** (rule H1); sibling-plan paths (Phase T) are **UNVERIFIED until merge** (rule H2).
- "05 §x" is `docs/superpowers/planning/2026-09-25-linear-parity/05-design.md` (revision 2);
  "L-n" is row n of the parity matrix in `01-linear-feature-inventory.md` as 05 §1 prices it. A
  row a task **closes** is built there and counts only when the task's acceptance commands pass;
  a row it only **serves** names the task that closes it; a row closed jointly names every task.
- Seams are the skeleton's `SW.n` (*Seams* table). `SW.18` is the W2 wire (`WorkPlan`, task 72);
  `SW.19` is the W3 records (task 99). Every surface test calls `expectNoPrediction(container)`
  (SW.8) and reads its data through the replica (SW.16).
- "Mutant" names the one wrong implementation a test exists to kill.
- Go tests run as `go test ./control-plane/... -race -count=1`, Hub integration rows with
  `-tags integration` against `control-plane/cmd/hub/compose.yaml`; desktop tests as
  `npm --prefix desktop test` and `npm --prefix desktop run typecheck`.
- Every desktop task follows the skeleton's *Global constraints*: list-focus keys only, one
  heartbeat clock, `tabular-nums`, `transform`/`opacity` motion only, Commit Mono facts at
  `--t-fact`, no Hub text on disk (ADR-H1). `OD-27`: no surface shows a prediction, a forecast, a
  target line or a percent-complete; `OD-28`: Commit Mono and Segoe UI Variable.
