# One-run OpenCode ↔ Ollama metadata observer

**Status:** offline diagnostic preparation for LOCAL-060. This script has not been run with Docker, OpenCode or Ollama. The offline tests use a fake loopback upstream. It neither validates coding capability nor authorizes execution of assistant text.

## Why a pass-through is necessary

Pinned OpenCode 1.18.34 (`aec0b9a6d8898f68f923aaf08b7306d931fd9d76`) has `chat.params` and `chat.headers` hooks in `packages/opencode/src/session/llm/request.ts`, but they do not expose the final prepared tool list and provider response together. `session/llm.ts` forwards `prepared.tools` to the AI SDK; `session/compaction.ts` resumes the selected agent/model after compaction. Ollama 0.40.2 `server/routes.go` populates native `ToolCalls` only when its tool parser recognizes them, and `openai/openai.go` maps those to OpenAI-compatible `tool_calls`. A text-shaped command is never an executable tool call. The failed Windows run retained neither the post-compaction request's tool offer nor the upstream response classification.

`opencode-ollama-observer.mjs` is a fixed local HTTP pass-through for `/v1/chat/completions` only. It binds `127.0.0.1:<explicit port>`, forwards to `127.0.0.1:11434`, requires a fresh bearer token and exact selected model, strips that observer token before forwarding, and has no arbitrary target/path/proxy mode. `/health` is authenticated and never calls Ollama. It accepts at most 64 chat requests, with at most four concurrent calls for OpenCode's title/summary work, during six minutes. Request body ≤1 MiB, response ≤8 MiB, metadata event ≤64 KiB, body deadline 10 seconds and per-call absolute deadline three minutes. It uses Node's HTTP stream backpressure; a client disconnect, timeout or owned retirement closes the upstream request. Effects after dispatch remain **uncertain**, never reported as a clean model cancellation. Receipt is a new exclusive private JSONL file, one bounded row per dispatched call; no prompt, tool arguments, response content, auth header, token or key is written. Text presence and byte count are metadata only. Truncated or unparseable upstream metadata is explicitly marked incomplete.

## Proposed one-run local plan — review before executing

1. Use the existing isolated UAT account/state and the exact saved local Ollama model. Verify the original endpoint is the unauthenticated host-local Ollama service on port 11434 and no other session uses the test connection. Do not use this observer for a protected remote endpoint or a saved upstream key. Create a fresh 32-byte random observer token privately; keep it in `LUCI_OLLAMA_OBSERVER_TOKEN` and never put it in a command argument, receipt, screenshot or handoff.
2. Start the observer as one positively owned host process with a private, pre-created receipt directory: `node scripts/diagnostics/opencode-ollama-observer.mjs --listen-port 11435 --model <exact-saved-alias> --receipt <private-path>/observer.jsonl`. It does not start Ollama or Docker. Check authenticated `GET http://127.0.0.1:11435/health` locally. Before inference, verify from the selected owned Docker route that `http://host.docker.internal:11435/health` reaches this exact observer; if loopback publication does not work on that Docker Desktop configuration, stop and retain the failed preflight rather than changing the bind to a LAN or wildcard interface.
3. In isolated Settings → Agent connections, change only the test local model endpoint from `http://127.0.0.1:11434/v1` to `http://127.0.0.1:11435/v1` with the temporary observer token as its key; retain the exact model ID, declared context/output, Ask permissions and reviewed task. Luci's `control-plane/internal/api/sessions_native.go:nativeDockerEndpoint` maps host-local configured endpoints to `host.docker.internal` inside the owned sandbox. Its saved local provider uses `{env:OPENCODE_LOCAL_API_KEY}` (`control-plane/internal/product/agent_credentials.go`), so OpenCode sends the observer token without embedding it in the config JSON. This is an explicit, temporary test-route revision, not silent interception of the original route. The observer forwards the original JSON request bytes unchanged and never forwards its bearer token to Ollama.
4. Run at most one guarded reviewed coding task under existing admission and human Ask authority. Preserve the ordinary native transcript and independent task/permission receipts. After termination or cancellation, stop the exact observer process, close its listener, reconcile the owned session and lease through normal product paths, and restore the original test connection with its original empty key. Keep the metadata receipt private. If the observer is lost after dispatch, retain an uncertain outcome; do not retry or execute text from a receipt.

The diagnostic distinction is narrow: tools absent from a post-compaction request point to configuration/continuation; tools present but no native `tool_calls` point to model/template/parser compatibility. A capability label or earlier successful read cannot prove that a later edit will succeed. A receipt marked `metadataIncomplete` or uncertain cannot support either conclusion.

Offline check: `node --test --test-timeout=5000 scripts/diagnostics/opencode-ollama-observer.test.mjs`. Fixtures cover arbitrary UTF-8 byte splits with byte-identical forwarding, fragmented indexed tool names across choices, nonstreaming text-shaped commands, truncated/malformed responses, unknown finish reasons, bad auth/model refusal, overlapping calls, client cancellation and absolute deadline. Only allowlisted finish reasons and offered tool names enter receipts; malformed or incomplete response metadata remains explicitly incomplete. These checks do not claim Windows reachability or real model behavior.
