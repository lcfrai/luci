# Assisted service topology: draft, review, save

This source adds a manual-only `deployment-blueprint` proposal to the existing project Luci conversation and existing model/schema/turn lifecycle. It adds no model loop, provider route or deployment action.

The optional snapshot binds the exact private saved blueprint revision/digest, current definition/design/configuration context and the existing bounded Git review digest. The full saved topology is included only within 48 KiB; a larger topology is explicitly omitted and cannot be amended by a model. The existing `captureGitReview` is reused once per optional snapshot with a three-second context budget and controller-selected project root. A failed capture marks topology assistance unavailable, rather than failing ordinary conversation. An unreadable private saved ledger becomes saved-topology-unconfirmed; an unrepresentable saved baseline becomes saved-topology-unsupported. Saved bodies are omitted without writing or normalizing the ledger. Configuration projection failure is omitted; absence/unconfirmed revision placeholders are unknown, never evidence that no blueprint exists. The existing saved-ledger reader itself still refuses compiler-incompatible records; this feature does not claim to make such a record readable by the saved API. Existing underlying file reads remain their established bounded implementation; this is not a new hard file-I/O cancellation guarantee or a filesystem transaction.

Proposals must match the exact saved revision, source/context and Git review digest. The pure deployment compiler and storage-safe checks validate at most eight services within 48 KiB. Existing service IDs/kinds must remain. Nonempty target, namespace, image, model/PVC, telemetry, environment and collector blocks must reuse captured saved references. Unknown references remain blank and become compiler decisions, or Luci asks a question. Values are proposed assumptions, not observed capacity, healthy services, image provenance, costs or successful deployment.

“Ask Luci to draft topology” opens the existing unsent composer. Normal model selection, current permissions and cost policy still govern sending. A response can be inspected, then “Review in Deploy” rechecks the current snapshot and sends one scoped in-memory intent to the existing editor. It never enters generic Apply, automatic coordinator targets, coordination origins/offers, or generic apply/recovery markers.

The receiving editor rechecks the exact saved baseline and current context before accepting the transfer. A dirty, busy or revoked editor is preserved; a source-changed proposal is refused. Transfer produces an unsaved editable draft and does not mark the conversation turn applied. Explicit Save checks the original Git review digest/source and baseline, then uses the existing blueprint revision/digest CAS, private history and idempotency. A source change after those reads is still subject to existing server context checks and later target source/check admission; no atomic worktree-change exclusion is claimed. Unknown saves retain their original attempt identity and require explicit existing recovery/readback behavior, never an automatic retry.

Successful Save reports the actual saved revision. Proposal origin remains visible while reviewing and in the immediate result. The existing blueprint ledger records the saving actor, source/context and canonical revision; it does not gain a fabricated conversation acceptance receipt. Reopening the old proposal after saving or source/context drift requires a fresh proposal. Existing target setup → Review → explicit Apply → Observe remains a separate user action and retains all source/check/access/policy/cost gates.

Shared source is supplied as contextual hunks over the post-feedback/personal integrations. Root's task-reuse preservation and the separate typed telemetry source are composed independently. The helper delegates to the existing typed blueprint compiler/parser and preserves typed fields; a collector block is treated conservatively as an exact saved reference, not authority to invent Secret names. No tests, typecheck/build, app/native execution, image acquisition or provider/model calls were executed while authoring this source.
