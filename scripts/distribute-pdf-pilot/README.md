# Isolated CFF1 PDF pilot (source only)

This directory is a separate Go module and is absent from `control-plane/go.mod`, the product build and release inventory. The private artifact PDF route continues to return 422. No dependency, font, toolchain archive, binary, PDF, or reader result has been acquired or produced for this pilot. `main.go` has no network package or downloader; it refuses a missing/non-exact font and an existing/non-owned output stage.

## Exact first experiment

Input is only original `NotoSansCJK-Regular.ttc` SHA-256 `b76b0433203017ca80401b2ee0dd69350349871c4b19d504c34dbdd80541690a`, face **0**, and fixed public text `日本語`. Read-only inspection of the existing exact-byte font reports face-0 CFF ROS `Adobe-Identity-0` and 65,535 glyphs; no font was acquired for this pilot. The pilot gets one glyph per original rune, places glyph zero first, asks pinned `tdewolff/font` to make a standalone CFF1 subset, reparses it and verifies original Unicode still maps to CIDs 1–3. It writes a one-page PDF 1.7 with `/Type0`, `/CIDFontType0`, `/Identity-H`, `/FontFile3 /Subtype /OpenType`, and a separate ToUnicode map from the original runes. A CFF2, TrueType, missing/repeated glyph, bad subset, changed CMap or limit violation refuses. It never substitutes another face, font, text, CID mapping or host font. The pinned subset source comments that the effect of CFF ROS on GID/CID identity is unclear (`sfnt_cff.go:1425`), so an actual standard reader must confirm subset ROS/CID behavior; source inspection cannot promote this route to valid PDF output.

`verify_pdf.py` is an independent Python reader for **this fixed PDF dialect**, not a general PDF conformance oracle. It follows the xref offsets and stream lengths, checks the embedded OpenType CFF table and CFF-specific font dictionaries, decodes the content CIDs through the ToUnicode stream and requires exact original text. It writes a private `verification.json` only after all checks. A separate standard reader's extraction and visual page check remain required before any product integration.
