## Protected operator contract for a later environment

The managed Linux worker uses its existing private `LUCI_E2B_CONFIG` JSON file. For `deployment.provider="azure"`, the configuration additionally requires:

The pinned upstream Azure Terraform module is **not suitable unchanged**: its published source opens 3000–3002 to configured client CIDRs and passes generated runtime secrets through custom data/Terraform state. Luci's separate protected module and host service supply a source-level deployment boundary. The later environment must not apply the upstream example as Luci's production boundary.

- Canonical lowercase `azureSubscriptionId`, `azureResourceGroup`, `azureScaleSetId`, numeric `azureInstanceId`, `azureDataDiskId`, zone, gateway host and the existing deployment scope/template/host generation. The endpoint is the selected private `https://{gatewayHost}`. AWS-only fields cannot substitute.
- `azureSecrets`: `vaultUrl`, user-assigned `clientId`, owner-only tmpfs `directory`, and separate `{name,version}` references for `apiKey`, `adminKey`, `attachKey`, `clientCert`, `clientKey`. Each version is exact lower-case 32-hex. Direct secret paths are refused for the Azure managed worker. A missing identity, secret, private Key Vault DNS result or valid client certificate refuses new cloud startup/effects. The trusted root CA remains a separate private file.
- `azureMount`: exact `mountPath`, ext4 `filesystemUuid`, `receiptPath`, `generation`, `controllerInstanceId`, `generationReceiptPath`, `generationReceiptDigest`. The on-disk owner-only disk receipt has `version:1`, the disk ARM ID, UUID, owner/scope and distinct controller/runtime host IDs. Its SHA-256 equals the existing `store.separationReceiptDigest`. The generation receipt has `version:1`, generation, controller instance ARM ID and disk ARM ID; replacement generations additionally name the previous generation and exact external fence-receipt digest. Its raw SHA-256 equals `generationReceiptDigest`. Both files and all Luci state/project/execution/staging/artifact paths must reside on the same mounted block device. The authoritative journal head remains in the existing directory store.
- `azureGatewayReceiptDigest` equals `e2bbe.GatewayReceiptDigest(gatewayHost, scope, generation)` and must match the private gateway's GET-only `/luci-gateway/receipt` body. A stale or missing route generation blocks fresh effects; the E2B task/admin auth and guest traffic remain separately checked.
- `envdOriginTemplate` is exactly `https://49983-{sandboxID}.{gatewayHost}` and `sandboxOriginTemplate` is exactly `https://8080-{sandboxID}.{gatewayHost}`. These match pinned E2B client-proxy host parsing and Luci's sandboxd port. DNS/TLS must route those private names to the selected gateway; never expose E2B's unauthenticated port 5008. A certificate trusted by the controller must cover the API host and the required guest hosts.

`go run ./cmd/azure-embed-host-bootstrap PRIVATE_HOST_CONFIG.json` reads exact-version `teamApiKey`, `adminToken`, `sandboxTokenSeed`, `gatewayServerCert`, `gatewayServerKey` and `gatewayClientCa` references from the host identity through private Key Vault DNS. The private host JSON names a host client ID **different** from the controller client ID, `gatewayHost`, private gateway/controller IPv4 addresses, exact scope/generation, a private tmpfs mount point, and byte-exact SHA-256 bindings for the upstream Compose YAML and its nonsecret base `.env`. It refuses base-environment overrides of managed secrets, invalid tokens/certificates and incomplete reads. It writes a nonsecret `gateway.json` that pins that generation, addresses and the staged TLS file paths for the gateway renderer, and prints only the generated private tmpfs directory path; `--retire PRIVATE_HOST_CONFIG.json STAGED_DIRECTORY` removes only that exact owned directory when it contains no unknown files. `scripts/azure-embed-host/service.py` now consumes these staged files on an image built from the immutable host archive, preflights the firewall/Envoy/Compose candidates, journals effects and rotates the gateway generation; live installation and automatic protected config delivery remain unverified/missing respectively. No secret values belong in Azure custom data, Terraform state or public logs.

`go run ./cmd/azure-gateway-config PRIVATE_GATEWAY_CONFIG.json` renders a static Envoy YAML document for an operator to inspect and deploy. Its private JSON names `gatewayHost`, a private `privateListenIp`, exact `controllerPrivateIp`, `scope`, `generation`, and protected `serverCertFile`, `serverKeyFile`, `clientCaFile`. It accepts no secret values and refuses missing, shared-readable, expired, mismatched or guest-DNS-incomplete TLS material. The renderer also serves that nonsecret route-generation receipt behind controller mTLS. It listens only on the selected private IP:443 and forwards pinned API routes to loopback:3000 and pinned guest routes to loopback:3002. Infrastructure must keep E2B ports 3000–3002 and 5008 unreachable from remote peers, preserve header and WebSocket behavior, and require the exact controller URI SAN. The renderer alone performs no host effect. The new dedicated-host service consumes its output and the private Terraform module defines VNet/DNS/NSG; neither was applied. The default-deny table belongs only on the selected dedicated host, never on a shared host. Actual Envoy route load and protected management traffic remain live gates.
