# CLOUD-042 — smaller runtime documentation payload

**Source candidate and focused validation; final compact package/native acceptance remain pending.** This capsule does not claim lower application RAM, faster interaction or a finished local product.

The extracted Linux candidate at `2da1a821b8456c20a858fb86ef87649ea917d9de` contained **3,587 files / 223,470,105 logical bytes**. Its validation evidence alone contributed **2,635 files / 67,844,220 bytes (64.7 MiB)**. Both portable scripts and native resources recursively bundled it, including frozen helpers, raw reports and screenshots. This was a metadata-only audit: archived/compressed savings were not measured. Inspected startup paths use separate state/project/web/runtime directories; no default indexing of this evidence was found. The metadata observation does not establish a RAM or latency effect.

The final eight-file candidate stages existing guides, root licences/NOTICE, operator/setup instructions and assets through one helper. It omits only the validation archive when source is clean, its exact revision is reachable from a locally cached official remote-tracking commit, and Markdown link handling is supported. Source-only destinations then point to that immutable revision. The remote check is bounded and offline: configured association is not live hosted-URL reachability or cryptographic publisher proof. Fork/unpublished/unknown/dirty source or ambiguous indented Markdown retains the full docs tree. No network authentication flow, credential logging or startup indexing is introduced.

Staged source bytes are bound to the exact commit. Git clean-filter semantics permit legitimate Windows CRLF worktrees while rejecting hidden content changes. Licences and runtime/cloud/bootstrap assets remain included. Native resources use the same staged guides; **build.rs is unchanged**. Existing native release-staging prerequisites remain, with platform-specific README guidance.
