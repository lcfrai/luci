# Runtime OCI distribution contract v1

Status: **producer/importer agreement proposed; no Docker effect is implemented by this document.** Controlling decision: [LOCAL-RUNTIME-DISTRIBUTION-RECONCILIATION-2026-10-14.md](../LOCAL-RUNTIME-DISTRIBUTION-RECONCILIATION-2026-10-14.md). Formal shapes: [manifest](runtime-oci-manifest-v1.schema.json) and [producer receipt](runtime-oci-build-receipt-v1.schema.json). Shared [metadata fixtures](../fixtures/runtime-oci-v1) are structural examples, not real image or source evidence.

The clean release package carries `runtime-oci-manifest-v1.json`, `runtime-image-linux-amd64.tar` and `runtime-build-receipt.json` as separate regular files under its runtime directory. The archive must be a **single-image tagless Docker-save tar**. The source-bound, hash-verified installed package, not an HTTP request or user-selected path, supplies the manifest and archive to the API. A missing/mismatched asset blocks ordinary installation; it never selects the local compilation fallback. The fallback remains an explicit advanced choice under the old limits and journal. The outer portable/native package carries one payload copy; the embedded Linux management core omits it. An older compatibility transfer must advertise and verify a required source-bound companion instead of pretending that its package is self-contained. Package manifests bind the manifest, build receipt and archive by exact bytes/hash; their verifier uses role-specific bounded payload caps instead of a global 512 MiB cap or unbounded reads.

## Canonical source inputs and producer recipe

`canonicalInputAlgorithm=luci-git-blobs-v1` is **new** and does not replace the advanced local builder's legacy `SourceDigest`/lease. [canonical_inputs.py](../../../scripts/runtime-oci/canonical_inputs.py) is the shared producer algorithm. At exact clean 40-hex `sourceCommit`, read Git blob bytes from `sandboxd/cmd/**`, `sandboxd/internal/**`, `sandboxd/vendor/**`, `sandboxd/go.mod`, `sandboxd/go.sum`, `images/sandbox/Dockerfile` and `images/sandbox/entrypoint.sh`; reject symlinks/submodules and enforce 8192 files/64 MiB total. Sort relative ASCII paths bytewise. Stage each blob unchanged as a regular `0644` file in a fresh private root with `0755` directories; the Dockerfile explicitly makes the installed entrypoint executable. Do not stage checkout CRLF, host file modes, .git, untracked files or a user-selected source directory. The digest is SHA-256 of, for each sorted file, ASCII `path`, NUL, `0644`, NUL, decimal byte length, NUL, lowercase hex content SHA-256, LF. `sourceFiles` is that complete sorted runtime-directory-relative inventory, including legitimate zero-byte regular source files. The [cross-OS fixture](../fixtures/runtime-oci-v1/canonical-cross-os.json) pins the digest independently of a Windows CRLF/0666 or Linux LF/0644 worktree.

The producer builds with the canonical stage and records the exact generated Docker context tar SHA-256, immutable base image IDs **and repo digests**, actual builder argv/version/limits/zero exit, stdout/stderr hashes, resulting config ID and archive hash/length in `runtime-build-receipt.json`. Four exact tool probes (sandboxd, Codex, Claude Code, OpenCode) record argv, exit status, version and output hashes. `cacheAssistance` and its log hash are producer-only; they never imply ordinary installed behavior. Probe evidence is hash-bound but is not a claim of live user-provider execution. The receipt is bounded metadata (1 MiB), has no credentials and its SHA-256 equals `producer.buildReceiptSHA256`. A reused payload built at an older `producer.buildSourceCommit` requires a bounded `runtime-source-reuse-v1.json` matching [its schema](runtime-oci-source-reuse-v1.schema.json), with original manifest/receipt copies, original trusted config/archive, new clean package source receipt and equal canonical input inventories/digests. `producer.reuseEvidenceSHA256` binds that file. No arbitrary relabel of a prior image. Ordinary new builds use matching source commits and omit the reuse field.

## Required cross-field and byte checks

1. Reject metadata over 1 MiB, duplicate JSON keys, unknown fields, noncanonical digests, invalid UTF-8 and target other than Linux/amd64. Require `sourceCommit` to equal the installed clean source receipt and `canonicalInputDigest` to equal the recomputed digest of the exact installed canonical runtime stage; `sourceFiles` lists **every** such regular file exactly once. An older build source additionally requires the prior trusted byte/config evidence above. `producer.dockerfileSHA256` equals the source-file entry for `images/sandbox/Dockerfile`; `producer.buildReceiptSHA256` equals the bounded sibling receipt. Receipt and manifest are provenance claims until package/producer verification succeeds.
2. Before any Docker mutation, inspect each path as a regular, nonlinked file in the selected installed package root. Stream the archive's exact `bytes` and SHA-256 with a hard 8 GiB cap and no full-buffer read. Scan tar headers with bounded member count and path size; reject links, devices, absolute/traversal paths, duplicate names, nonregular entries, unexpected members or mismatched member lengths/hashes. Normalize producer Docker-save output to **only** `configID.json`, one or more distinct `<layer-id>/layer.tar`, and `manifest.json`, in lexical path order; no directory entries, `repositories`, OCI auxiliary files or tags. `archive.members` is that complete sorted inventory. Each uncompressed `layer.tar` member SHA-256 equals its `diffID` hex. Docker 28 may emit auxiliary files; producer normalizes the stream without rewriting config bytes/ID. A normalization failure blocks publication.
3. The tar's one `manifest.json` entry names exactly `image.configPath` and `image.layerPaths` in order. The config file's SHA-256 equals the hex part of `image.id`; each layer tar matches its member digest, and each uncompressed layer digest matches the corresponding `image.diffIDs` and config `rootfs.diff_ids`. All paths are distinct safe relative paths. The config OS/architecture, user, working directory, entrypoint, exposed ports, absence of volumes/OnBuild and declared CLI versions match the manifest and pinned release policy. The version fields alone do not prove actual CLI execution; producer and installed harness probes remain required evidence.
4. `licenses` is an exact `licenses/`-relative path/hash/length inventory of packaged notices, each with component, version, grant and provenance for Debian, globally installed npm harnesses and Go dependencies. Validate exact inventory against the installed package. `sourceFiles` paths are relative to `runtime/`; licence paths are relative to the package root. The shared image/config must carry no allocation/job/instance execution-ownership labels; producer provenance labels are separate. Only the small derivative gets exact allocation labels. No manifest field grants execution authority. The current actor/policy, engine/instance, exact allocation and fresh whole-machine capacity are checked again before each Docker effect.

## Effect ownership

The importer journals **archive import**, **small allocation-derived image creation**, and **tag publication** as separate exact effects. `ImageLoad` receives only the preverified tagless stream. A lost load response may reconcile by exact immutable ID/config readback; no response, missing image or Docker timeout alone settles it. The shared payload is never deleted as an allocation-owned image. A tiny derivative from the immutable imported ID adds the current allocation/job/scope/source labels without a Go, apt or npm RUN. Only that derivative may become the configured runtime tag after reauthorization and exact readback. Cancellation/restart retain uncertain effects and capacity charges until positive settlement or supported engine-retirement evidence. Docker tags have no CAS; refuse a different observed tag and keep the existing engine-wide publication lock.

`image.id` is the immutable **shared payload** configuration ID. The derivative has a different image ID and exact allocation labels. Import demand is separately measured and admitted; do not reuse the former 1 GiB RUN demand or lower the host reserve to pass. A fresh observer monitors actual host capacity throughout and cancels only owned effects. Installed proof must include no local heavy RUN, host/WSL memory and responsiveness, a real upstream Docker task and cleanup; metadata fixtures alone do not close LOCAL-033.
