# PDF private pilot insertion v1 — frozen source contract

This is an **unwired source contract** for one fixed CJK CFF1 pilot. It grants no acquisition, compilation, Docker action, render, reader execution or public export. The original Debian metadata/GPG/readelf observations are unaccepted trust evidence; see the [retrospective](../evidence/pdf-debian-metadata-retrospective-20261016/README.md). No provisional hash may fill an independently reviewed source receipt. The existing pilot writes `pilot.pdf` under its required empty `--out-dir`; a container tmpfs would disappear at stop. The only proposed output transport is the guarded private **host bind stage** below, not a late Docker copy or an arbitrary host path. The [stage/SDK seam](pdf-private-pilot-stage-sdk-seam-v1.md) pins the exact current writer path, selected Docker SDK fields and remaining unsupported ownership gates.

## Allocation and deadline contract

One controller-generated 32-hex `AttemptID` and exact 64-hex private `ScopeDigest` produce two deterministic 64-hex allocation IDs: SHA-256 of UTF-8 `luci-pdf-pilot-v1\n` + scope digest + `\n` + attempt ID + `\nrenderer` or `\nreader`. Both are persisted **before any Create**. Each ID permits at most one Create; unknown ACK retains its claim and allows exact readback/retirement only. A separate `PDFPilots` record in the existing shared host ledger charges **one 512 MiB pilot allocation**, never two simultaneous 512 MiB child reservations. A separate 64 MiB pending host-capture allowance and 48 MiB owned-output-stage disk reservation are charged through the normal host/disk demand, in addition to the ordinary Docker/VM launch overhead; these are not a second child allocation or a cap on daemon/page-cache memory. The renderer must be positively retired (exact selected engine, instance, CID, labels/config, stopped/absent observation and durable receipt) before the reader Create. No new child is started while either role has an unknown effect.

The controller records `reservedAt=T0` and derives `rendererPhaseEnd=T0+40s`, `readerPhaseEnd=T0+80s`, `wholeEnd=T0+120s`; these are immutable. Renderer Start-to-exit is at most **30s**, including no implicit extension for human/tool waits. Renderer Prepare/Create/Start/exit and bounded output read must complete by `rendererPhaseEnd`. Reader Start-to-exit is at most **30s**; reader Prepare/Create/Start/exit and bounded result read must complete by `readerPhaseEnd`. No reader Create after that time. `T0+80s` to `wholeEnd` is reserved for exact cleanup/publication; early failure transfers all remaining time to cleanup. A dedicated watchdog starts at reservation, keeps the exact CIDs as they become known and attempts Retire on its own selected-engine call lane and bounded context at phase/whole deadline or pressure/cancel, without waiting on blocked Create/Start, capture or receipt publication locks. If the selected engine itself is unavailable, retirement stays unknown and capacity remains held. A failed/unknown Retire retains the durable lease, stage and full charge after `wholeEnd`; time alone is never absence. Request cancellation stops new starts but cannot cancel the watchdog's independent exact-owned retirement context.

## Durable renderer-to-reader handoff

The API's private stage opener, under `ExecutionStateDir/pdf-pilots/<AttemptID>`, creates `renderer/pilot-<AttemptID>` and `reader/pilot-<AttemptID>` using rooted handles, exact parent identity, private ancestry and a **reviewed numeric nonroot writable ownership/ACL** for the child binds. The renderer child is empty before Create. It records volume/file IDs and resolved paths before Docker Create. If that permission arrangement cannot be proved on the selected OS/filesystem, Prepare refuses; it must not chmod a project, user home or shared parent. The stage is outside project/credential paths and its 48 MiB disk reservation covers one 16 MiB PDF, at most 1 MiB text, at most 16 MiB PNG and bounded metadata; exhaustion refuses rather than dropping output. The renderer's fixed configuration may bind only the reviewed font read-only and the exact `renderer/pilot-<AttemptID>` directory read-write at `/out/pilot-<AttemptID>`; no tmpfs output or other write mount. Its current `--out-dir /out/pilot-<AttemptID>` then creates `pilot.pdf` once. Docker post-Create inspect must match the exact stage source, destination, ownership profile, command, env, image digest, limits and labels before Start.

After positively observed renderer exit, the API opens only `renderer/pilot-<AttemptID>/pilot.pdf` through the retained stage directory handle with no-follow/nonblocking semantics, verifies one ordinary file/link count and exact file identity before/after, rejects extra stage entries, reads at most **16 MiB+1**, computes SHA-256, and publishes `bytes`, digest and file identity durably **before** renderer retirement and before reader allocation. A read/capture/publication error or changed identity is unknown/failure, never output success. The independent watchdog may retire the renderer while this read blocks; that makes the output unavailable and forbids reader Create. Once capture and exact renderer retirement are durable, the API removes renderer write authority and rechecks the same file/digest. The reader gets that exact file as a **read-only** bind; Prepare and pre-Start inspect verify the same retained digest/identity. A verified, packaged reader driver is still missing; only such a driver could execute the two fixed standard-reader commands sequentially inside **one** reader child, without shell, network or external fetch. Its `reader` output bind is separately guarded and bounded: UTF-8 text <=1 MiB, one PNG <=16 MiB, no extra files. The semantic check compares the exact retained PDF digest and fixed original Unicode text, not just a readable PDF header. Reader exit, bounded capture and positive retirement are separate facts. Stage removal occurs only after both owned children and receipt publication are positively settled; unknown paths remain private for readback.

## Additive source ownership

Cloud owns dedicated `internal/backend/pdf_pilot.go` identity/profile/executor types and `internal/api/pdf_pilot_private.go` request/lease validators plus inert fixtures. A later, separately reviewed `internal/backend/dockerbe/pdf_pilot.go` would implement the fixed selected-SDK adapter. The bridge reviewer owns **all** shared `execution_leases.go`, admissions, runtime-install, Product and projection edits; this proposal is an insertion contract only for those files. The shared insertion must add `PDFPilots` to the existing 2 MiB/4096 ledger bounds, purpose collision checks, reservation view, every worker/check/preview/image/document/assembly admission, pressure response and exact recovery. `distribute-work.lock` is acquired before shared ledger mutation; the existing workbook/artifact wrapper remains 256 MiB, while only the private PDF path asks for 512 MiB. The private API caller must use current actor/source/engine authority inside the final reservation mutation and again before **each** Create/Start; after unknown effects it permits only exact recovery/retirement, never an authority-bypassing replacement.


The additive admission signatures proposed for shared review are `(*API).admitDistributeWorkWithCharge(ctx context.Context, policy product.SwarmSchedulerPolicy, chargeBytes uint64) (func(), error)` and `(*executionAdmission).reservePrivatePDFPilot(ctx context.Context, request pdfPilotRequest, currentActor management.ExecutionAuthorizer, resolveCurrentSource pdfPilotSourceResolver, policy product.SwarmSchedulerPolicy) (executionDecision, pdfPilotLease, error)`. `pdfPilotSourceResolver` is a **future private verified source-catalogue reader**, not a caller-provided receipt or fallback to the provisional metadata JSON. It must return the exact `pdfPilotCurrentBinding` from current approved product/source state under the final mutation exclusion; actor and source must be re-read after any queued wait. The dedicated pure `validPDFPilotAdmissionBinding(request,current,now)` checks exact actor, 5-second observation freshness, approved revision/digest and source/image/font/binary/package equality but explicitly does **not** authenticate the resolver. No such reviewed approval/source resolver currently exists, so reserve must fail closed. On Start, recheck current grants and exact immutable binding again without substituting a new actor/source into an already-created child.

The dedicated backend interface is purpose-specific: `Prepare`, `Create`, `Start`, `Inspect`, `Retire`, and exact launch-fence/readback operations for a fixed role/spec. It has no `Pull`, `Build`, arbitrary command, path lookup, URL, credential or public handler. The API's stage reader is the only bounded capture path; the SDK adapter cannot select an output host path. Every mutation publishes a bounded durable receipt before the next effect. The two allocation IDs, role, selected image and source/binary/font/reader receipts, expected command/config/mount digest, stage identities, actual CID and observed outcome remain immutable across restart. Caller/adapter/fence source tests must cover replay, cancellation, blocked publisher, blocked stage read, exact-CID watchdog retirement, newer actor/source revocation, and two-child nonoverlap. These tests use inert executors only until separately authorized runtime verification.
