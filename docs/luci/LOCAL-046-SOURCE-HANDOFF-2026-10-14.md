# LOCAL-046 OpenCode conversation source handoff — 14 October 2026

The local Windows tester observed an OpenCode 1.18.34/Ollama conversation with a 1 GiB Docker limit, no Docker OOM and 738 generated tokens. The launcher exited 2: OpenCode's `--file` path treated `prompt.txt` as a text attachment and the returned analysis echoed its line-truncated source context, missing the current request near the end of a 3,141-character serialized line. Existing strict result validation correctly refused that output; no reply was accepted.

Pinned upstream source: `sst/opencode` tag `v1.18.34`, commit `aec0b9a6d8898f68f923aaf08b7306d931fd9d76`, `packages/opencode/src/cli/cmd/run.ts` at its stdin input (`Bun.stdin.text()` and `resolveRunInput`) and session prompt construction. Its piped stdin is the message text; `--file` creates a separate file part. Luci's read-only `luci-analysis` agent, exact configured model and bounded JSON event parser remain in place.

The launcher now sends a bounded text message containing the complete prompt and the exact generated response schema over stdin, with no file attachment. This preserves the current request after a long context line and tells the selected harness to return only one schema-matching JSON object. The API still rejects unknown fields, malformed/fenced output, stale proposal identity and unreviewed work; this path does not grant tools or infer success from provider text.

The first installed retest confirmed full stdin delivery but found an independent serving-window truncation. Ollama logged a 6,178-token prompt against a 4,096-token serving context with roughly 2,048 tokens reserved for output. The saved model's training context is larger, but it does not change the actual server window. A byte cap alone cannot prove token fit, and a 512-token output budget cannot cover a normal complete specification proposal.

The read-only OpenCode analysis route now provides `limit.context=8192` and `limit.output=2048` for a local Ollama endpoint. A short custom analysis agent prompt replaces OpenCode's large default coding prompt; pinned upstream `session/llm/request.ts` selects `agent.prompt` in place of `SystemPrompt.provider`. The identical exact response schema is transmitted compactly: the orchestrator contract is 5,950 bytes instead of 20,061 after Python indentation. Before OpenCode generation, the launcher sends the full prompt to the exact selected model via Ollama `/api/generate` with `raw:true`, `stream:false` and `num_predict:1`. This is a bounded model call, not a free tokenizer lookup. Its `prompt_eval_count` reports evaluated input tokens; pinned Ollama `runner/ollamarunner/runner.go` truncates oversize input to the serving limit, which saturates this count near that limit. Luci checks `/api/ps` for the loaded model's actual `context_length` and digest. It requires at least 8,192 tokens and evaluated input + 2,048 output + 2,048 system/template allowance to fit. A final read-back rejects a changed loaded context/digest. The 14,000-byte limit is only a transport/memory bound; it is not treated as a token estimate. The existing-model alias [setup recipe](LOCAL-MODEL-CONTEXT-SETUP-2026-10-14.md) avoids a model download or global setting. Actual resource admission and host monitoring remain unchanged. It does not change OpenCode coding-session limits.

Focused Python-backed Go tests cover the long context line and tail request, equivalent parsed schema delivery, fenced-output refusal, actual served-window/count acceptance, refusal of a 4,096-token window, refusal of high-token text below the byte cap, and pre-launch oversize refusal. Distinct `local_model_context_limit` and `local_model_context_unverified` failures are retained without raw provider output. These source checks do not establish actual model quality or provider compatibility with the embedding preflight.
