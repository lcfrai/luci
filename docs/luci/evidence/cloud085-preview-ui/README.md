# CLOUD-085 checked-source preview controls

This is controlled frontend/API validation for explicit saved local-preview permission, exact Dockerfile/port/runtime-configuration delegation, saved-route reuse, current Deploy authority, uncertainty readback, and truthful local-preview status. It does not demonstrate Docker execution, real-provider quality, native/browser layout, responsiveness, public deployment, or the complete personal coordinator journey.

The response validator requires the exact project/release/check/source binding, local target, verified parent checks and an observed preview witness before ready status. `Open Deploy` navigates to the existing Deploy tool; it does not promise exact release focus. Policy writes omit unrelated settings. Browser recovery retains build options without consent or a trusted configuration revision. A failed optional metadata read can be explicitly discarded, but retained mutation requests and browser-storage errors still block new work.

## Boundaries

Preview permission is separate from public deployment and does not grant current team permissions or spend authority. Preview plans require exact check delegation and configuration revision. Lost or discarded mutation outcomes remain retained until authoritative readback; GET refresh never replays a POST. Existing preview work is not cancelled by pausing new previews. A saved route with unsupported newer delivery fields is blocked instead of silently dropping its intent.

The personal Luci main-entry gap remains separate: the existing conversation is still a secondary project pane in this checkpoint. Backend background work can advance accepted continuations; creating a fresh continuation for a later approved amendment currently requires the active conversation surface. Cross-project reasoning, autonomous approval, complete preview-to-live delivery and broad acceptance are not claimed.
