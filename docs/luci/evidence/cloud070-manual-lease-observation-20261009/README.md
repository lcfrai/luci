# CLOUD-070 — prompt reconciliation of confirmed-absent manual capacity

P2 prospective production feature. Base source: 29931afc5b31ae9b9bd7b8973a7e3fdb840609a3. External staging only; root manages integration.

Installed299 attempt11 retained an ordinary manual 1024 MiB / 1000 mCPU reservation through the 35-second helper deadline after the exact Docker object changed from removing to absent. Its final helper operation timed out with almost no remaining budget. This supports delayed idle reconciliation, not a permanent lease leak or incorrect CPU admission. Existing production reconciles ordinary reservations on the next admission. The retained actual attempt and fixture are unchanged and are not a passing C054 receipt.

The proposed observer runs through the existing trusted scheduler observation hook even with an empty queue. Manual observation has its own one-second context alongside the existing task observer, and both join before the turn returns. It examines at most 128 lease entries and attempts at most eight candidates, retaining unattempted peers across slow turns. It never supplies user authority, starts or destroys a process, changes source, records task success, or frees capacity at typed Exit.

Eligibility requires an exact own-scope backend-settled lease with LaunchGuard=1, an ordinary exited registry row with immutable allocation identity, and no conflicting receipt. Docker's optional read-only absence capability validates the full immutable reference and requires actual unambiguous NotFound for both the reusable logical name and that original reference. Any present, renamed, foreign, removing, unknown, cancelled or mixed-error result retains capacity. Unsupported backends retain existing on-demand behavior.

The observer uses the existing process restart guard and per-child durable lifecycle lock. Managed Restart now participates in the same durable lock and rereads its row under it. Backend observation occurs outside the global admission lock. A nonblocking local mutex acquisition and the existing context-aware shared lock guard the final durable update, which rechecks the complete captured lease and current row generation. No-op or stale observations do not rewrite the ledger. Admission's existing private path preparation is shared with lifecycle locking so a supported controller configuration with an absent execution directory can still restart.
