# Private PDF pilot caller and ownership proposal v1

**State: source proposal only.** No public PDF route, compiler, renderer, reader, image acquisition, Docker action or product export is enabled by this document. The Debian metadata observations in [the retrospective](../evidence/pdf-debian-metadata-retrospective-20261016/README.md) are provisional and cannot fill an immutable source or trust field. `scripts/distribute-pdf-pilot` remains isolated from the production Go module.

## Proposed typed seams and ownership

| Owner/file | Additive source seam | Required refusal |

Keep its command/profile distinct from `DocumentExtractionExecutor`. | Unsupported transport/header profile, missing selected immutable image, unexpected label/mount/command/resource, uncertain SDK ACK or unknown original input. |

The state mutation order is `distribute-work.lock` **then** `executionAdmission.mutate` under its ordinary durable `leases.lock`; do not invert it in recovery or pressure response. Reserve one immutable attempt before Create. Durable states are `reserved → create-unknown/created → starting/running → exited/capture-pending → retirement-unknown/finished`; recovery reads exact engine/instance/CID/config/fence before settling. Renderer and independent reader have separate refs and positive retirement facts within one attempt. Captured bytes are evidence only after exact bounded read, digest, required semantic checks and durable receipt publication; a valid PDF structure does not imply child cleanup.

## Fixed profile proposed for later source review

One immutable selected Linux image would have to contain the exact renderer and independently pinned reader executables at reviewed paths. Renderer and reader each use no network, read-only root, nonroot numeric UID/GID, no credentials/socket/privilege/capabilities, no restart/log retention, exact read-only original bindings and one private owned output stage. Docker configuration and post-Create inspect must agree on `Memory=MemorySwap=536870912`, `NanoCPUs=1000000000`, `PidsLimit=32`, `NetworkMode=none`, `IpcMode=none`, mounts, command/environment and labels. The renderer has an absolute 30-second compute deadline; the reader has a separately bounded deadline and output. `main.go`'s 32 MiB font/intermediate aggregate and 16 MiB PDF limits are additional checks, not substitutes for the hard cap. Both children must retire by exact CID before charge release; an emergency stop cannot wait for a blocked reader/publisher.

**Unset fields:** immutable image ID and build/source receipt; executable paths/hashes and ABI; original font wrapper-to-font/notice proof; seven Go module ZIP and original-grant closure; Poppler archive-to-library/notice closure; selected stage ownership and disk budget; private adapter source and actual inspect/readback; hard-limit/retirement observation. Host-installed fonts/readers, the document-extractor image, the existing Go cache and the provisional Debian metadata inventory cannot fill these fields. Missing any field stops the caller before an effect.

The first source-only implementation review should inspect inert request/ledger/profile validators and fault fixtures: wrong engine/actor/input/image, stale host sample, concurrent 256 MiB work, lost Create or publication ACK, restart with unknown child, cancelled capture, reader error after renderer exit, and blocked reader during emergency retirement. No test may construct a real Docker client or render a PDF at this stage. A later effect proposal must independently cover exact acquisition, builder/runner containment, original bytes/grants, and the runtime image before any private run.
