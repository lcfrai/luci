# C080 classic Docker preview completion and adapter contract follow-up

The preserved original backend accepted any full aux.ID as terminal success. Pinned Docker 28.3.3 emits an aux ID after every build stage; its outer backend emits the final Successfully built marker only after all stages. The new regression reproduced six false-success cases on the unchanged original backend: first-stage-only EOF, mismatched marker, marker before aux, aux after marker, later mismatched marker, and extra marker text. The before run failed one top-level test and six subtests; three subtests passed. This is an observed defect, not a timing inference.

The corrected backend retains the last full aux image ID, invalidates prior completion on a later aux, requires the exact final marker with its matching 12-character prefix, consumes bounded EOF, checks errors, and proves owned intermediates absent before success. Final image inspection still checks full identity and labels. A fully observed failed build can settle with an error only after complete EOF and absence; incomplete/ambiguous results remain unsettled. It does not replay a build.

Additional corrections bound directory reads with LimitReader even after stat, check base-size/reserve arithmetic before uint64 overflow, and restrict reserved ownership validation to actual LABEL keys after logical continuation joining. Ordinary comments, RUN text and LABEL values mentioning luci remain supported. Dynamic keys, parser directives and ambiguous escapes remain unsupported.

The platform network contract now compares the immutable network ID and exact project with the trusted adapter's derived platform-instance namespace, instead of confusing it with the backend instance ID. Tests exercise the actual derived namespace and product extra-label shape. Mandatory ownership labels remain backend-assigned; the product's redundant luci.preview key is removed in the separate product-label-followup capsule. Runtime requests must be server-built; browser label assertions are not accepted.

Fixed validation: 16 top-level tests plus 60 subtests passed, exit 0, 2.89 seconds, no timeout. The before run used 956 source/config/module/embed bindings and the fixed run 958, each unchanged before/after. Go 1.26.3, GOMAXPROCS=2, package parallelism 1, default vet, offline modules, 120-second test timeout and 180-second wall bound. Exact invocation, wrapper, complete logs and bindings are retained. No Docker runtime was started and no broad suite was rerun.

`backend-followup.patch` applies to the exact preserved four-file original backend tree; six files change or are added. `source/fixed` is the complete seven-file tested backend overlay. The before-terminal overlay is source/original plus only source/fixed/.../preview_terminal_regression_test.go. Both overlays are explicitly mapped by their receipt files. Repository and workspace inputs are recorded separately. The original root compile/failed/fixed evidence remains unchanged and is included as exact compressed bytes, bound by original-bindings.json; those earlier checks did not cover this newly reproduced terminal defect.

These corrections are external staged source, not an installed or production-readiness claim. Base images still must exist locally before bounded preparation. Missing-base provisioning and uncertain-build cleanup/recovery need product integration; an unresolved build cannot safely release capacity solely from a missing response. Actual Docker launch, restart, recovery, and the complete product journey remain gates.
