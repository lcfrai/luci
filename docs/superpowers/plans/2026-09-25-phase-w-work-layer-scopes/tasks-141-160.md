**141 — an agent's edit to an issue or brief is a proposal, shown as a diff.** Closes **L-130**
(05 §1 group I: *"An agent's edit to a brief or issue is a **proposal** (`text·A`), shown as a diff,
that a person accepts"*). The rule it rests on is 05 §3.6's authorisation row, *"an agent writes
only comments on its own owner's behalf"*, and phase 4's `4-D2` (*"A model-written answer is not
inherited until a person accepts or changes it"*, phase-4 plan `:143`). So an agent never writes an
issue revision: its edit is an `ic-` comment of kind **`edit_proposal`**, `text·A`, whose body is
`EditProposal{baseRevision int, title?: AuthoredText, description?: AuthoredText, servesAdd
[{briefKey, criterionId}], servesRemove [{briefKey, criterionId}], why [key]}` (every `why` key
resolvable through `/v1/refs`, 05 §1 L-52's rule). The kind is **not** in SW.19's set (task 99:
`note`, `evidence_proposal`, `negotiation`) nor in SW.20 (task 114); **if neither part carries it,
that is a gap to close in 114** (the kind constant, the body's `Validate`, the fake's rule and the
migration's kind CHECK), not here. Writers: task 136's assists (written as the person who invoked
them, `text·A`, through the ZDR gateway, L-157) and a W3 Orchestrator acting for its owner. On the
brief side the proposal is phase 4's `model_drafted` answer (P4 task 03's `Answer.Author`,
`person`·`model_drafted`·`model_accepted`), which phase 4 already refuses to settle or materialise.
