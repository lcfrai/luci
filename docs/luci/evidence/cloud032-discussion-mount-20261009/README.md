# Defer unopened discussion presentation

A newly selected project previously built its entire hidden conversation history, storage controls, provider controls and composer before anyone opened the discussion. The correction defers this presentation until its first explicit or programmatic open. One atomic state records both open state and whether presentation has ever opened, so an open/close sequence cannot lose that record through effect timing. Once opened, the same controls remain mounted when closed within the same project scope. Existing project/account/workspace scope keys reset the presentation.

Context reads, job observation, pending-request and browser-draft recovery, permissions, decision lookup, amendment review and visible ProjectUnderstanding remain in the parent. This does not cache authority or project context, remove requests, defer a verification action, change navigation selectors or change any acceptance threshold.

The same four new regressions ran against unchanged da8 production source and then against this correction. All four originally failed because the untouched discussion already allocated hidden presentation; 105 existing cases were deliberately excluded by the before-run name filter. The unchanged new tests then passed as part of **210 passing assertions in eight affected files**, with zero failures or skipped tests. **TypeScript passed.** The original failure logs and exact before/after sources are retained. Input hashes remained stable during each command.

New coverage protects unopened current understanding plus recovered/pending original request records; continuing active-job observation before presentation opens; first programmatic focus; exact composer node/draft retention after closing; and new-project isolation. The full existing orchestrator, ProjectUnderstanding, ConversationStorage, composerRecovery, DefinitionWorkspace, AppShell, TeamWorkspaceProvider and store draft-registration suites cover related recovery, read denial, late responses, amendments, drafts and navigation. The recorded invocation also names `src/hooks/useProjectDraft.test.tsx`, which does not exist; it matched no file and is not counted as coverage. There were eight actual test files. No full frontend suite was repeated.

**Installed latency after this candidate remains unmeasured.** The separate clean da8 idle run still fails switch p95: 317.287164 ms against 300 ms, with input p95 66.501146 ms passing 100 ms. Source inspection establishes unnecessary hidden presentation allocation, but timings do not prove it caused the six slow switches or guarantee this correction meets the gate. All 400 original actions, 32 separate trace-followup rows, raw failures and immutable thresholds remain unchanged. A matching installed run and the sustained four-project workload are still required.

`run-check.py` records activation, exact command arguments, raw reporter/stdout/stderr, and before/after source/config/package-lock hashes. `source-before/` pairs unchanged base production with the new regression bytes; `original-test/` preserves the original base test file; `source-after/` contains the candidate. `source-change.patch` is the complete two-file change.
