# LOCAL-063 native turn read boundary (source only)

Source base `58913457cd487dfbace6ac358e4e0b6d87ffe298`; candidate `310dfb33ca57f746af615587180681ed0fd9373a` exposed a synchronous native read from `sessionJSON`. That made each list poll wait up to 750 ms per active OpenCode row. The corrected implementation keeps list and session serialization store-only. A person can request one selected session's turn from `GET /v1/sessions/{id}/native-turn`. At most two such reads run per API process; each has a 750 ms transport deadline and inherits request cancellation. The response is an exact generation and last-output-bound, content-free observation or `unknown`. The UI discards an old observation after restart or new output. It never treats a final assistant turn as a candidate, check, or executable instruction. No installed Windows or model run used this route.
