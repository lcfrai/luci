The managed Linux worker reads an **optional** absolute `LUCI_E2B_CONFIG` path at startup. With it unset, cloud execution stays unavailable and cannot fall back to Docker. The operator file is a private JSON document outside Git; it supplies `endpoint`, absolute `apiKeyFile` and `attachKeyFile` paths, optional `rootCaFile`, `controllerStateDir`, `stagingDir`, `envdOriginTemplate`, `sandboxOriginTemplate`, and the pinned `deployment`, `template`, `limits`, `store`, `taskMaxSeconds`, `taskEstimatedCostMicros` objects. It also requires `modelEgressDomains`: one to eight exact lowercase DNS names such as `api.openai.com` and `api.anthropic.com`, selected for the saved upstream connection. Wildcards, CIDR/IP rules, local/internal names and broad Internet egress are refused. The selected model's default or explicit HTTPS base URL must match one listed name before allocation; a changed/unlisted endpoint blocks launch. The pinned Embed `SandboxNetworkConfig` explicitly makes `allowOut` entries take precedence over `denyOut`, so Create sends these exact domains together with `denyOut: ["0.0.0.0/0"]` and private inbound traffic. This is configured policy, not live guest egress proof; the actual template/network boundary must be tested before acceptance. The two guest origin templates each contain exactly one `{sandboxID}` and must resolve to protected HTTPS without direct management port 5008. The attach-key file holds 32 random bytes as 64 hex characters. The worker refuses absent/linked/public/oversized private files, an unverified deployment scope, unsupported template/limits, nonprivate staging, mismatched off-host store identities or unavailable current managed execution authority. Exact field limits and identities are defined by `cmd/api/e2b_config.go` and `backend/e2bbe`. Do not copy provider/model credentials or the key into the JSON file, task archive or repository.

`template.buildId` is now required in the private operator file. The worker reads that exact pinned provider build status at startup and before a new task allocation; only `ready` permits Create. This read-only provider preflight does not prove the guest image contents match `template.buildDigest`. A signed source/build inventory and real guest validation remain required.

The same bounded preflight now checks the provider's current template listing: its last successful build must still be the configured build ID, with the configured CPU/memory and a private template. Because Create accepts `templateID` rather than a build ID, an operator must also prevent concurrent template republishing across that read/Create interval. This reduces stale-template admission; it does not make the provider selection atomic or prove image bytes.

The private operator file also requires `adminApiKeyFile` (an absolute private file containing the runtime's separate admin API key) and `hostNodeId` (the selected node from the pinned runtime). Startup reads the authenticated `/nodes` endpoint; new Create attempts repeat a bounded read and wait or refuse when the pinned ready node has no observed sandbox slot, CPU or memory. This read uses the admin credential only on the protected management origin and never places it in task input, metadata or journals. It is a conservative, non-atomic admission snapshot, not proof of KVM, actual provider quota, a price quote or a future Create decision. With either operator field absent, selected cloud execution refuses startup; local Docker remains separate.

The pinned OpenAPI requires `X-Admin-Token` for `/nodes`; the ordinary task API key uses `X-API-Key`. Luci keeps these request headers and private files separate.

The first adapter accepts only AWS `m8i.xlarge`, `m8i.2xlarge`, `m8i.4xlarge` or `m8i.8xlarge` as operator-selected nested-virtualization host candidates. ### Concrete controller-host durability

`NewDirectoryStore(StoreConfig)` provides private filesystem objects, not a new server or cloud service. Journal and input/output artifacts are content-addressed, hash-read back and retained within explicit byte/object budgets. `Checkpoint.Claim` grants exactly one fenced writer, matched to the current durable head and local journal; a released writer cannot publish or release a successor. Another process/store handle is excluded by the existing statelease. `RestoreController` requires the reviewed current head and a fresh destination, refuses stale/implicit/overwriting restores, and keeps unknown old-host charges. Artifacts remain available through independent controller and store reopen without re-executing a task.

The store requires distinct declared controller/runtime host IDs and a separation receipt, rejecting a declared same-host layout. **Actual physical separation is still a deployment/configuration acceptance gate**. A disk on the same replaceable host is not off-host backup merely because it has another directory. Provider-host loss/restoration and storage persistence across actual failure remain unverified. No record or artifact is silently garbage-collected to admit work; a full store refuses further publication/allocation. Archival/retention and operator recovery are still required. File readers supplied by wiring need transport deadlines because a context cannot preempt an arbitrary blocking Reader; partial copies must be discarded on error.

### Private guest transport and one-shot upstream bootstrap

`Controller.Guest` supplies a transport only from that controller's exact private Create grant and current allocation/authority. `Config.GuestOrigins` must resolve **operator-configured private verified HTTPS origins**, never a URL from model context or a provider response. Runtime `cf536c28` explicitly declares envd `0.9.0` in `packages/envd/pkg/version.go`; this exact pin is distinct from the SDK's lower minimum feature versions. File requests carry envd and private traffic tokens; WSS `/attach` carries the existing Luci bearer token and traffic token, never the management key or envd token. The original sandboxd binary message protocol and4MiB limit remain intact. Upload/download/readback/Start operations and attach handshakes are registered before effects with the guest and its owning controller. Closing either cancels accepted client operations; the controller retains its state/checkpoint lease until those operations return. `GuestTransport.Close` refuses new work and joins accepted operations before closing idle clients. Returned WebSocket lifetime/closure still belongs to its caller. Client drain is not remote mutation settlement or whole-VM cleanup; uncertain outcomes retain their charges. [The shutdown regression](evidence/cloud084-guest-lifecycle/README.md) preserves the original early-release/late-upload failure and correction.

- `StageInput` verifies the bounded archive before upload, posts it once to `/luci-transfer/input.tar` as root, then verifies the complete remote readback. Failed/lost acknowledgement is uncertain and never automatically retried. It neither extracts nor executes the archive. `ReceiveOutput` validates a separate exact output archive into `DirectoryStore`; output claims are still untrusted until independent checks/review.
- **Guest output production now has source implementation and controlled kernel/filesystem tests, but is not wired into controller collection or a deployed template.** The root collector loads the exact protected launch/input records, requires an observed frozen dedicated cgroup, and creates bounded source/change manifests and `/luci-transfer/output.tar` with a hash-bound receipt. Actual root/cgroup/KVM permission and escape tests remain open. The controller must still invoke this once, verify durable returned bytes and baseline changes, then route them through existing review/integration before automatic successful teardown. An envd process-stream end remains separate from upstream native task exit; sandboxd remains a server after its task exits.
- The pinned envd uploader creates new files with0666 subject to umask and preserves an existing file's mode on truncation. The trusted template **must precreate `/luci-transfer/input.tar` as root:root0600 under a protected root-owned directory**. Bootstrap refuses a world/group-readable upload instead of silently repairing a wrong template. This template has not been built or validated on an actual Embed VM.
- `StartGuest` accepts a transport minted by the same controller, current revision/authority and a trusted `LaunchSpec` from the existing upstream adapter. It supports only named `codex`/`claude` commands, bounded argv, attach token and the narrow selected provider environment. Task data cannot select a root command, loader environment, provider credential or connection policy. `ConnectionRevision` binds trusted connection configuration without recording/hashing secret values in the journal.
- The controller durably checkpoints `LaunchRequested` and a configuration digest **before** one pinned Connect `process.Process/Start`. It invokes only `/usr/local/bin/luci-microvm-bootstrap` with exact archive/project/task/attempt/operation/source/context arguments; root's bootstrap then verifies and protects the source/context and reserves its separate one-shot launch marker before the existing entrypoint/sandboxd starts the upstream CLI. A Start PID acknowledges envd's fork, not sandboxd readiness, a natural task exit, useful output, or verified completion.
- Unknown/malformed/lost Start acknowledgement cannot replay, including after controller reopen. Cancellation during the request preserves its intent and settles that exact owned VM after acknowledgement. A short caller/ACK deadline does not become the remote process lifetime through `Connect-Timeout-Ms`: the process budget is bounded by the allocation expiry; cancellation detaches observation without proving process death. Missing outcomes keep the reservation until exact VM settlement.
- `ObserveLaunchKernel` reads only the fixed root-private `/luci-work/attempt/launch-kernel.json`, requires the exact acknowledged PID/VM/request/source/context and checkpoints its boot/cgroup identity. `ObserveNativeExit` then reads the existing authenticated sandboxd typed Exit frame; stdout status text and envd End cannot stand in for native outcome. Current authority, bounded reads and exact identity are retained. A natural nonzero exit can be recorded without declaring success. Neither observation releases capacity or integrates source. An uncertain external checkpoint must be re-acknowledged before repeated readback reports success; reviewed cancellation can wake a held observer and settle only its exact owned VM. [Selected source/race evidence](evidence/cloud084-native-observation/README.md) includes restart, held cancellation, malformed protected receipts and unchanged-history checks, while actual VM/provider execution remains open.
- Create's envd/traffic credentials are stored separately in private controller state, bound to operation/request/sandbox/deployment; no credential enters allocation checkpoints, task bundles, logs or public receipts. They are currently retained in that private state until operator retirement; a production credential-retention policy remains required. A restored journal without its private grant supports observation/cancellation only. GET sandbox detail omits the traffic token, and POST connect can resume/extend paid lifetime, so it is never an implicit read-only recovery fallback. Model/attach credential persistence remains the existing registry/connection layer's responsibility.

The wire implementation copies only the pinned generated protobuf/Connect bindings (one Go import relocation), preserving the original Apache-2.0 grant, and pins `connectrpc.com/connect v1.18.1` without importing the infrastructure module or building a custom RPC parser.
