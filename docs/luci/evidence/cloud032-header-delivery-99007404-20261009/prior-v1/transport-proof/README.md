# C032 tiny transport proof

The sole browser attempt passed 18 recorded checkpoints. This used a small controlled loopback HTTP server and Chromium only. No installed application, main C032 diagnostic, Vite, Docker, worker, provider, or model execution occurred.

The original frozen idle handler was extracted byte-for-byte from actual/sustained.mjs, bound to SHA256 18429d2a6497cfec582c8565b572b3ca567b756f2f9d403efd79b6b405719dc2. A transparent registration wrapper counted handler invocations and enforced the proof's request cap; every actual proof request reached the unchanged handler. Its same-origin and closing/background-failure/workflow-failure restrictions and mutation logging remained active throughout. Baseline and defer used the same Playwright context.route mechanism and the same separate CDP session with Fetch enabled at Response stage.

For successful overview and scheduler GETs, Fetch.getResponseBody captured the full original response before a deferred-delivery checkpoint. The browser promise was still unsettled at that checkpoint. Explicit release used Fetch.continueResponse with only requestId: no replacement body, fulfillment, route.fetch, or replay. The delivered status, complete exposed headers, and body matched the original server response exactly. Each request was seen once by the server and once by the original route guard. Baseline used immediate continuation after the same full-body capture.

403 responses, POSTs, and an improper path were continued immediately, without full-body capture or holding. The original guard logged the POST and blocked cross-origin, closing, fixtureError, and workflow-failed requests before they reached the server. A natural AbortSignal cancellation after full-body capture rejected the browser promise with AbortError before release; cleanup attempted Fetch.continueResponse and received Invalid InterceptionId because the browser had already cancelled that interception. No request was replayed. This proof observed zero pre-body natural cancellations and one post-body cancellation. The pre-body cancellation branch was not exercised, and this proof establishes no backend-work preservation claim for it.

The proof observed 12 browser requests, 10 response pauses, at most 153 captured body bytes, and at most 37.73 ms per pause. Its fail-closed caps were 16 browser requests/response pauses, 64 KiB per captured body, and 1 second from response pause through release; the hard process stop was 88 seconds. Passing evidence comes from the explicit capture/unsettled/release/delivery checkpoints, not a timing threshold or performance claim. Cap-overflow fault injection was not performed.

No paused response IDs or owned browser PIDs remained. The separate CDP session was disabled and detached, Chromium and the HTTP server closed, and the exact owned profile was removed. The frozen driver and runner hashes remained unchanged. COMMANDS.json retains the exact command and observed exit; attempt-1.log is original merged stdout and stderr. The result contains binding, server/guard/pause observations, cancellation and cleanup; raw.jsonl contains chronological checkpoints and protocol outcomes.

This is evidence of transport coexistence for the tested Chromium/Playwright build, not approval to run the main diagnostic or proof that delayed responses isolate React commits alone.
